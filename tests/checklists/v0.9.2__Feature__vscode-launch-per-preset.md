# Human Test Checklist: v0.9.2 -- `.vscode/launch.json` per preset

**Target version:** 0.9.2
**Ships with commit:** `v0.9.2: feat(layers): .vscode/launch.json per preset; the structure's Python-only one removed` (TBD until committed)
**Companion automated tests:** 14 in `tests/test_layers_vscode.py`, plus the updated two-language composition in `tests/test_layers_claude_plugin.py`.

## What this is

v0.9.2 gives every preset its own VS Code debug configurations, so a new project can be stepped through from its first commit. The automated tests prove each file parses, names the right debugger and points its build task at a task that exists. Only a person can prove the part that matters: that pressing F5 in VS Code actually stops at a breakpoint. This checklist walks each preset through that.

## Prerequisites

1. Windows 10/11; VS Code with the Python extension (it provides `debugpy`) and the C/C++ extension (it provides `cppvsdbg` and `cppdbg`); Python 3.10+; Node 20+ with npm; for the C/C++ presets, Visual Studio 2022 or its Build Tools, and vcpkg for the CMake app.
2. Scratch folder and isolation, once per shell:

   **cmd.exe**:
   ```cmd
   set SCRATCH=%TEMP%\rk092
   mkdir %SCRATCH%
   cd /d %SCRATCH%
   set REPOKIT_LICENSE=mit
   set GIT_CONFIG_COUNT=2
   set GIT_CONFIG_KEY_0=commit.gpgsign
   set GIT_CONFIG_VALUE_0=false
   set GIT_CONFIG_KEY_1=tag.gpgsign
   set GIT_CONFIG_VALUE_1=false
   set REPOKIT_COMMON_SOURCE=C:\code\git-repokit-common
   ```

   **PowerShell**:
   ```powershell
   $env:SCRATCH = "$env:TEMP\rk092"; New-Item -ItemType Directory -Force $env:SCRATCH | Out-Null; Set-Location $env:SCRATCH
   $env:REPOKIT_LICENSE = "mit"; $env:REPOKIT_COMMON_SOURCE = "C:\code\git-repokit-common"
   $env:GIT_CONFIG_COUNT = "2"; $env:GIT_CONFIG_KEY_0 = "commit.gpgsign"; $env:GIT_CONFIG_VALUE_0 = "false"
   $env:GIT_CONFIG_KEY_1 = "tag.gpgsign"; $env:GIT_CONFIG_VALUE_1 = "false"
   ```

   **POSIX (Git Bash)**:
   ```bash
   export SCRATCH=/tmp/rk092; mkdir -p "$SCRATCH"; cd "$SCRATCH"
   export REPOKIT_LICENSE=mit REPOKIT_COMMON_SOURCE=/c/code/git-repokit-common
   export GIT_CONFIG_COUNT=2 GIT_CONFIG_KEY_0=commit.gpgsign GIT_CONFIG_VALUE_0=false GIT_CONFIG_KEY_1=tag.gpgsign GIT_CONFIG_VALUE_1=false
   ```

   Every create: `repokit create <name> <flags> --no-push` with stdin closed (`< NUL` in cmd.exe, `< /dev/null` in bash).
3. **The F5 routine** used below: open the created folder in VS Code (`code <folder>`), open Run and Debug, check the dropdown lists the configurations named in the step, set a breakpoint on the first line of the entry point, choose the first configuration, press F5.
4. **Reset:** close the VS Code window and delete the created folder.

## High-Value Verification (~10 minutes)

### HV.1 -- A Python package stops at its breakpoint

- [ ] **Steps:** `repokit create py-pkg --language python --no-push`; the F5 routine with a breakpoint in `py_pkg/cli.py`'s `main`.
- [ ] **Expected:** the dropdown shows `py-pkg --version`, `Python: current file`, `pytest: tests`, `pytest: current file`; F5 stops in `main`; continuing prints `0.1.0`. No "unknown debug type" warning.
- [ ] **Why this matters:** Python is most of what gets created here; this is the case people will hit first.

### HV.2 -- A JavaScript script and a TypeScript package

- [ ] **Steps:** `repokit create js-scr --language js-ts --with script --no-push`, F5 with a breakpoint in `js-scr.js`. Then `repokit create ts-pkg --language js-ts --no-push`, `npm install` in it, and run the `npm test` configuration with a breakpoint in a test file.
- [ ] **Expected:** the script stops and prints its version; `npm test` compiles and the debugger attaches to the test run (breakpoints in compiled TypeScript bind only when source maps are on; record what you see).

### HV.3 -- A CMake app builds and stops

- [ ] **Steps:** `repokit create cm-app --language c-cpp --no-push`; in VS Code run the task `Configure` once (Terminal > Run Task), then the F5 routine with a breakpoint in `src/main.cpp`.
- [ ] **Expected:** `Build Debug` runs before the launch; the debugger stops in `main`; continuing prints the version. Off Windows, the gdb configuration does the same after a single-config build.
- [ ] **Why this matters:** a C/C++ launch that cannot find its binary is the most common way these files go wrong.

### HV.4 -- Two languages, and generic

- [ ] **Steps:** `repokit create duo --language python,js-ts --no-push`; `repokit create plain --language generic --no-push`.
- [ ] **Expected:** `duo` prints `Note: .vscode/ holds python's debug configurations; js-ts's were not merged in (add them to .vscode/launch.json by hand)` and its `launch.json` is Python's; `plain` has no `.vscode\launch.json`. Judge whether the note tells you what to do.

## What the automated tests DO cover

| Area | Test file | Count |
|---|---|---|
| every built preset's launch.json: strict JSON, no tokens left, names its debugger, `justMyCode` off for debugpy, any `preLaunchTask` names a task the preset ships | `tests/test_layers_vscode.py` | 11 |
| the package, script and hook entry points | same | 1 |
| two languages: the primary's file and the report | same, and `tests/test_layers_claude_plugin.py` | 2 |
| a generic create has none; the CLI prints the note | same (integration) | 1 |

## What the automated tests DON'T cover

- that VS Code recognises each debug type with the extensions people actually have
- breakpoints binding, and F5 stopping where expected
- the build tasks running in the terminal VS Code opens (PATH, Developer Command Prompt, vcpkg)
- TypeScript source maps under `npm test`
- whether the two-language note reads well

## Reporting issues found

Note the section and step, capture the Debug Console output and the task output, keep the scratch folder, and file an issue that names this checklist and the commit.

## Cleanup

Close the VS Code windows; delete the scratch folder: `rmdir /s /q %TEMP%\rk092`, `Remove-Item -Recurse $env:TEMP\rk092`, or `rm -rf /tmp/rk092` (or `dz safedel` it).
