# Human Test Checklist: v0.9.3 -- the GitHub half

**Target version:** 0.9.3
**Ships with commit:** `v0.9.3: feat(github): labels, the two issues as #1 and #2, pins, discussions, topics, the pypi environment` (TBD until committed)
**Companion automated tests:** 12 in `tests/test_github_setup.py` (9 unit tests on a fake gh, 2 through the CLI with a stub gh, 1 live test skipped unless a throwaway is named); 1 changed pin in `tests/test_github_create.py`.

## What this is

v0.9.3 makes `repokit create --github` do what `/github-issues-setup` and `/create-project` did by hand once the repository existed. The tests prove the calls and their order against fakes, and one live check proved them on a private throwaway (`djdarcy/repokit-throwaway-20261024-1`, 2026-10-24). This checklist is for what a person sees on GitHub and for the accounts and organisations a test cannot stand in for. It creates real repositories: use throwaway names and delete them afterwards.

## Prerequisites

1. `gh` logged in (`gh auth status`) to the account the throwaways should live under; Python 3.10+.
2. A scratch folder, a license, unsigned commits, the vendoring source:

   **cmd.exe**: `set REPOKIT_LICENSE=mit` · `set GIT_CONFIG_COUNT=2` · `set GIT_CONFIG_KEY_0=commit.gpgsign` · `set GIT_CONFIG_VALUE_0=false` · `set GIT_CONFIG_KEY_1=tag.gpgsign` · `set GIT_CONFIG_VALUE_1=false` · `set REPOKIT_COMMON_SOURCE=C:\code\git-repokit-common` · `mkdir %TEMP%\rk093 && cd /d %TEMP%\rk093`

   **PowerShell**: `$env:REPOKIT_LICENSE="mit"; $env:GIT_CONFIG_COUNT="2"; $env:GIT_CONFIG_KEY_0="commit.gpgsign"; $env:GIT_CONFIG_VALUE_0="false"; $env:GIT_CONFIG_KEY_1="tag.gpgsign"; $env:GIT_CONFIG_VALUE_1="false"; $env:REPOKIT_COMMON_SOURCE="C:\code\git-repokit-common"; New-Item -ItemType Directory -Force "$env:TEMP\rk093" | Out-Null; Set-Location "$env:TEMP\rk093"`

   **POSIX**: `export REPOKIT_LICENSE=mit GIT_CONFIG_COUNT=2 GIT_CONFIG_KEY_0=commit.gpgsign GIT_CONFIG_VALUE_0=false GIT_CONFIG_KEY_1=tag.gpgsign GIT_CONFIG_VALUE_1=false REPOKIT_COMMON_SOURCE=/c/code/git-repokit-common; mkdir -p /tmp/rk093 && cd /tmp/rk093`
3. Creates run with stdin closed (`< NUL` / `< /dev/null`). The repositories are **private** unless `--public` is given.

## High-Value Verification (~10 minutes)

### HV.1 -- Everything, on a private throwaway
- [ ] **Steps:** `repokit create rk-test-a --language python --github --github-setup all --topics demo,test < NUL`
- [ ] **Expected:** `GitHub:` lines for nine labels, `#1 Roadmap`, `#2 Quick Notes -- Bugs, Features, Ideas`, both pinned, discussions on, the topics, the `pypi` environment, ghtraf's commands, and the reminders. On GitHub: the repository is private; the Issues tab shows the two issues pinned at the top; Settings shows Discussions on and the `pypi` environment; the About box shows the topics; the push went through (the hook ran the package's tests and they passed).
- [ ] **Why this matters:** it is the whole of `/github-issues-setup` in one command.

### HV.2 -- With Dependabot on, the issues still get #1 and #2
- [ ] **Steps:** `repokit create rk-test-b --language python --extras dependabot --github --github-setup labels,issues < NUL`; wait a few minutes for Dependabot.
- [ ] **Expected:** the Roadmap is #1 and the Quick Notes #2; any Dependabot pull request takes #3 or later.

### HV.3 -- Another account is refused
- [ ] **Steps:** put `{"license": "mit", "github": {"username": "<a handle that is not yours>"}}` in a scratch `~/.repokit/config.json` (point `HOME`/`USERPROFILE` at a scratch folder), then `repokit create rk-test-c --language generic --github --github-setup labels < NUL`.
- [ ] **Expected:** a refusal naming both handles; no repository is created on GitHub.

### HV.4 -- An organisation
- [ ] **Steps:** with an organisation you can create in, `repokit create rk-test-d --language generic --github --org <org> --github-setup labels,issues,pin < NUL`.
- [ ] **Expected:** the repository and its issues are under the organisation; pinning works there too.
