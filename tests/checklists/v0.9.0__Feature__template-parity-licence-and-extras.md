# Human Test Checklist: v0.9.0 -- template parity: the licence parameter and the extras

**Target version:** 0.9.0
**Ships with commit:** `v0.9.0: feat: template parity -- the licence parameter, the extras, the parity regression` (TBD until committed)
**Companion automated tests:** 20 tests in `tests/test_licenses.py` (6), `tests/test_license_cli.py` (7), `tests/test_extras_cli.py` (5), `tests/test_template_parity.py` (2); the full suite at this version is recorded in the CHANGELOG commit.

## What this is

v0.9.0 is the milestone of the 0.9.x line: a `repokit create` reproduces the project tree git-repokit-template gave, for every language the tool builds. Two user-visible surfaces arrive: `--license` (a required parameter with a catalogue, a file form and `none`) and `--extras` (the template's optional files behind names). The automated tests prove the behaviour; this checklist is for what they cannot see: how the refusal reads at a terminal, whether `--help` is legible, what a person's real global config produces, line endings on Windows, the push hook's speed, the wheel's contents, and the tag and release that only the maintainer can do.

## Prerequisites

1. Windows 10/11 with Git for Windows (cmd.exe, PowerShell and Git Bash all available), Python 3.12, `pip install build`.
2. This checkout of git-repokit at the target commit; a sibling checkout of git-repokit-common at `..\git-repokit-common`; the template checkout at `C:\code\git-repokit-template` (read-only; only the parity test reads it).
3. **Isolation.** Every create below runs in a scratch directory with a scratch HOME, an unsigned git identity and the sibling checkout as the vendoring source. Set these once per shell and keep them for the whole run:

   **cmd.exe**:
   ```cmd
   set SCRATCH=%TEMP%\rk090
   mkdir %SCRATCH%\home\.repokit
   set HOME=%SCRATCH%\home
   set USERPROFILE=%SCRATCH%\home
   set GIT_CONFIG_COUNT=2
   set GIT_CONFIG_KEY_0=commit.gpgsign
   set GIT_CONFIG_VALUE_0=false
   set GIT_CONFIG_KEY_1=tag.gpgsign
   set GIT_CONFIG_VALUE_1=false
   set REPOKIT_COMMON_SOURCE=C:\code\git-repokit-common
   set PYTHONPATH=C:\code\git-repokit
   git config --file %HOME%\.gitconfig user.name "Ada Example"
   git config --file %HOME%\.gitconfig user.email "ada@example.invalid"
   ```

   **PowerShell**:
   ```powershell
   $env:SCRATCH = "$env:TEMP\rk090"; New-Item -ItemType Directory -Force "$env:SCRATCH\home\.repokit" | Out-Null
   $env:HOME = "$env:SCRATCH\home"; $env:USERPROFILE = "$env:SCRATCH\home"
   $env:GIT_CONFIG_COUNT = "2"; $env:GIT_CONFIG_KEY_0 = "commit.gpgsign"; $env:GIT_CONFIG_VALUE_0 = "false"
   $env:GIT_CONFIG_KEY_1 = "tag.gpgsign"; $env:GIT_CONFIG_VALUE_1 = "false"

   git config --file "$env:HOME\.gitconfig" user.name "Ada Example"
   git config --file "$env:HOME\.gitconfig" user.email "ada@example.invalid"
   ```

   **POSIX (Git Bash)**:
   ```bash
   export SCRATCH=/tmp/rk090; mkdir -p "$SCRATCH/home/.repokit"
   export HOME="$SCRATCH/home" USERPROFILE="$SCRATCH/home"
   export GIT_CONFIG_COUNT=2 GIT_CONFIG_KEY_0=commit.gpgsign GIT_CONFIG_VALUE_0=false GIT_CONFIG_KEY_1=tag.gpgsign GIT_CONFIG_VALUE_1=false
   export REPOKIT_COMMON_SOURCE=/c/code/git-repokit-common PYTHONPATH=/c/code/git-repokit
   ```

   Every create below is `python -m repokit create ... --no-push` run inside `%SCRATCH%` with stdin closed (`< NUL` on cmd.exe, `< /dev/null` on POSIX; PowerShell: append `| Out-Null` is not enough, run it from cmd or bash when the prompt matters). Never run a create in a real checkout.
4. **Reset between sections:** delete the created project folders under the scratch directory (`rmdir /s /q`, `Remove-Item -Recurse`, `rm -rf`) and empty `%SCRATCH%\home\.repokit\config.json` when a section says so. The scratch HOME's `.gitconfig` stays.

## High-Value Verification (~5 minutes)

### HV.1 -- Nothing named: the refusal reads well and writes nothing

Validates: the licence is required; the refusal names the catalogue; no folder is left behind.

- [ ] **Steps:** with no `config.json` in the scratch HOME and `REPOKIT_LICENSE` unset, in `%SCRATCH%`: `python -m repokit create hv1 --language python --no-push < NUL` (cmd) / `< /dev/null` (bash).
- [ ] **Expected:** a non-zero exit; one error line beginning `Error setting up repository: no licence named: pass --license <id>, --license file=<path> or --license none, or set `license` ...` followed by the catalogue list on the same line; no `hv1` folder exists.
- [ ] **Why this matters:** a first-time user with no config must learn in one line what to type; a stray half-made folder would be the worse failure.

### HV.2 -- The house config produces the template's tree

Validates: the global-config route (licence, extras, GitHub handle and organisation) and the parity itself.

- [ ] **Steps:** write `%SCRATCH%\home\.repokit\config.json`:
  ```json
  {"license": "gpl-3.0", "license_private": "all-rights-reserved",
   "extras": ["all"], "github": {"username": "djdarcy", "organization": "DazzleTools"}}
  ```
  then `python -m repokit create hv2 --language python --description "A demo" --no-push < NUL`.
- [ ] **Expected:** `hv2\LICENSE` begins `GNU GENERAL PUBLIC LICENSE` / `Version 3, 29 June 2007`; `.github\FUNDING.yml` has `github: djdarcy`, `ko_fi: djdarcy`, `buy_me_a_coffee: djdarcy`; `.github\release-template.md` has `git clone https://github.com/DazzleTools/hv2.git`; `ROADMAP.md`, `docs\platform-support.md`, `.vscode\settings.json`, `.github\dependabot.yml`, `stale.yml`, `pull_request_template.md`, `tests\one-offs\README.md`, `tests\output\.gitkeep` all exist; `.repokit.json` has `"license": "gpl-3.0"` and the nine extras in table order.
- [ ] **Why this matters:** this is the milestone in one command; if it fails the line's claim is false.

### HV.3 -- The flag beats the config, and a private repository takes its own default

Validates: `--license` precedence and `license_private`.

- [ ] **Steps:** with HV.2's config in place: `python -m repokit create hv3a --language generic --private-repo --no-push < NUL` and `python -m repokit create hv3b --language generic --private-repo --license mit --no-push < NUL`.
- [ ] **Expected:** `hv3a\LICENSE` begins `Copyright (c) 2026 Ada Example. All rights reserved.`; `hv3b\LICENSE` begins `MIT License` with `Copyright (c) 2026 Ada Example`; `.repokit.json` says `all-rights-reserved` and `mit` respectively.
- [ ] **Why this matters:** the private default is what most people expect until they loosen it (the maintainer's words); the flag must still win.

### HV.4 -- Every language receives the licence and the extras

Validates: the pieces are structure, not Python's.

- [ ] **Steps:** `python -m repokit create hv4c --language c-cpp --no-push < NUL` and `python -m repokit create hv4j --language js-ts --no-push < NUL` (HV.2's config still in place).
- [ ] **Expected:** both have the GPL `LICENSE`, `.github\FUNDING.yml`, `dependabot.yml`, `stale.yml`, `ROADMAP.md`, `.vscode\settings.json`; the js-ts one also has its `package.json`, the c-cpp one its CMake files.
- [ ] **Why this matters:** "for any language type" is the second half of the milestone.

### HV.5 -- The wheel is honest

Validates: the fixed wheel test's reverse inclusion, and the catalogue shipping.

- [ ] **Steps:** in the git-repokit checkout: `dz safedel build` (if `build\` exists), then `python -m build --wheel --outdir %TEMP%\rk090\whl`, then `python -c "import zipfile,glob; z=zipfile.ZipFile(glob.glob(r'%TEMP%/rk090/whl/*.whl')[0]); n=z.namelist(); print(sum('repokit/licenses/' in x for x in n), 'licence files;', sum(x.endswith('.pyc') for x in n), 'pyc;', [x for x in n if x.endswith('ci.yml')])"`.
- [ ] **Expected:** `20 licence files; 0 pyc; []` (19 texts plus `LICENSES.md`; no bytecode; no pre-0.7.3 `ci.yml`).
- [ ] **Why this matters:** a stale `build\lib` shipped a dead file for two weeks; this is the check that stops it.

### HV.6 -- The push hook is quick

Validates: `test-command` in `pyproject.toml` runs the unit class.

- [ ] **Steps:** in the git-repokit checkout, time `bash scripts/repokit-common/hooks/pre-push origin https://example.invalid/x.git < NUL` (the hook reads the ref list from stdin; an empty one still runs the checks) or push to a throwaway remote.
- [ ] **Expected:** `Running tests...` then `106 passed, 101 deselected` within about 5 to 10 seconds; the whole hook under 30 s.
- [ ] **Why this matters:** seven-minute pushes were the complaint; four seconds is the fix, and only on this repository.

## Section 1: the licence parameter, the rest of the surface

### 1.1 `--help` is legible
- [ ] **Steps:** `python -m repokit create --help`.
- [ ] **Expected:** `--license ID|file=PATH|none` and `--extras NAME[,NAME...]` / `--no-extras` appear with their help text wrapped sanely at 80 columns; no `__RK_` tokens, no markdown.

### 1.2 The or-later notice
- [ ] **Steps:** `python -m repokit create s12 --language generic --license gpl-3.0-or-later --no-push < NUL`.
- [ ] **Expected:** `LICENSE` opens with `Copyright (c) 2026 Ada Example`, a blank line, one paragraph naming the GNU General Public License, version 3 or (at your option) any later version with `SPDX-License-Identifier: GPL-3.0-or-later`, then the full GPL text. Read the paragraph: it should read as a notice, not as a template.

### 1.3 The file form keeps bytes
- [ ] **Steps:** make `%SCRATCH%\own.txt` with CRLF endings (Notepad, or `printf 'A\r\nB\r\n' > own.txt` in bash); `python -m repokit create s13 --language generic --license file=%SCRATCH%\own.txt --no-push < NUL`; `fc /b %SCRATCH%\own.txt s13\LICENSE` (cmd) / `cmp` (bash).
- [ ] **Expected:** identical bytes; `.repokit.json` says `"license": "file:own.txt"`.

### 1.4 An unknown id
- [ ] **Steps:** `python -m repokit create s14 --language generic --license wtfpl --no-push < NUL`.
- [ ] **Expected:** non-zero exit, `unknown licence 'wtfpl'; the catalogue has: ...`, no folder.

### 1.5 `repokit adopt --license`
- [ ] **Steps:** in a scratch folder with an existing `LICENSE` file and a `README.md`: `python -m repokit adopt . --license mit --no-push < NUL`; then in a folder without a LICENSE, the same.
- [ ] **Expected:** the existing LICENSE is kept (`.repokit.json`: `existing`... or the flag's choice when `--license` is passed: the flag wins, as for create); the folder without one gets MIT.

## Section 2: extras

### 2.1 Named, in the table's order
- [ ] **Steps:** empty the scratch `config.json` (`{}`); `python -m repokit create s21 --language generic --license mit --extras stale,funding --no-push < NUL`.
- [ ] **Expected:** `.github\stale.yml` and `FUNDING.yml` only; `.repokit.json` `"extras": ["funding", "stale"]` (table order, not given order); FUNDING's handles read `YOUR_GITHUB_USERNAME` because no handle is configured, which is the visible cue to set `github.username`.

### 2.2 `--no-extras` over a config list
- [ ] **Steps:** HV.2's config back in place; `python -m repokit create s22 --language generic --no-extras --no-push < NUL`.
- [ ] **Expected:** none of the extras; `"extras": []`.

### 2.3 An unknown extra
- [ ] **Steps:** `python -m repokit create s23 --language generic --license mit --extras sponsors --no-push < NUL`.
- [ ] **Expected:** non-zero exit, `unknown extras sponsors; known: funding, dependabot, ...`, no folder.

### 2.4 Line endings on Windows
- [ ] **Steps:** in HV.2's `hv2`: `git ls-files --eol .github/FUNDING.yml .github/dependabot.yml ROADMAP.md LICENSE`; and `file .github/dependabot.yml` in Git Bash.
- [ ] **Expected:** the index column shows `i/lf` for every file (the first commit normalised them through `.gitattributes`); the working tree may show `w/crlf` on Windows. The rendered files on disk may be CRLF before the commit; that is the platform newline, not a defect. **Record** what you see: if `i/crlf` appears, the `.gitattributes` is not doing its job and that is a bug to file.
