## What this is

Not every Python project is a package. djdarcy, 2026-10-18: "A lot of my old python tools were never intended for pypi and were just run locally. I had minimal cicd / release components since they were often just huge monolothic files. We still want to allow for SIMPLE projects to a certain extent". `python/script` is that floor: one module named after the project, a plain `VERSION` file it reads for `--version`, a two-test `tests/`, a `.repokit-common.toml` so the vendored hooks keep `VERSION`, the CHANGELOG and the tags in step, and a CI that compiles the module and runs it with `--version`. Nothing to install. `script` is a build-facet choice, exclusive with `pypi` and `setuppy`. What the automated test cannot judge: whether the floor is the right height -- too bare to be useful, or still carrying more than a local tool wants.

## High-Value Verification (~4 minutes)

### HV.1 -- The floor, created and run

- [ ] **Steps:** in `SCRATCH`: `repokit create my-tool --with python/script --no-push`; `dir my-tool` / `ls -a my-tool`; `python my-tool/my-tool.py --version`; `python my-tool/my-tool.py --help`; `python my-tool/my-tool.py`.
- [ ] **Expected:** at the root: `my-tool.py`, `VERSION` (`0.1.0`), `.repokit-common.toml`, `tests/test_version.py`, the structure's files (README, CONTRIBUTING, CHANGELOG, `.gitattributes`, `.gitignore`, `private/`, `scripts/repokit-common/`), `.github/workflows/ci-python.yml` and nothing else under workflows; **no** `pyproject.toml`, `setup.py` or `requirements.txt`. `--version` prints `0.1.0`; `--help` names `my-tool`; a bare run prints the hello line. **Judge:** is this the floor you had in mind, or does it still carry too much (the tests folder? the CI?) or too little (a `src/` folder? a `requirements.txt` stub)?

### HV.2 -- The version tool knows the file

- [ ] **Steps:** in `my-tool`: `python scripts/repokit-common/sync-versions.py --check`; then edit `VERSION` to `0.1.1` and run `python scripts/repokit-common/sync-versions.py` and `--check` again.
- [ ] **Expected:** `--check` exits 0; after the bump the tool reports the CHANGELOG's compare links and the sync in step. `.repokit-common.toml` reads `version-source = "VERSION"`.

### HV.3 -- Its CI is a script's CI

- [ ] **Steps:** read `my-tool/.github/workflows/ci-python.yml`.
- [ ] **Expected:** a Python matrix that compiles `*.py`, runs each with `--version`, and runs `tests/` when the folder exists; no `pip install -e .`, no `python -m build`, no twine. The README badge names `ci-python.yml`.

### HV.4 -- The bare name, and the refusal

- [ ] **Steps:** `repokit create s --with script --no-push`; `repokit create x --with pypi,script --no-push`; `repokit list python`.
- [ ] **Expected:** `s/.repokit.json` records `"archetype": "python/script"`; the second create fails with `'pypi' and 'script' are both a build for python; pick one` and leaves no `x/`; `list python` shows `python/script = script` and `build one of: pypi, script, setuppy`.

### HV.5 -- The hooks on the first commit

- [ ] **Steps:** in `my-tool`: `git add -A && git commit -m "first"` (the hooks are installed with the vendored copy).
- [ ] **Expected:** the pre-commit hook runs and passes; it says nothing about a missing `_version.py` (the source is `VERSION`). A push to a scratch remote would run `tests/` through the pre-push hook (optional).
