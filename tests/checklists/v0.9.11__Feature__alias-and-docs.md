# Human Test Checklist: the dazzle-git-repokit alias, adopt and the license, and the documentation

**Target version:** 0.9.11
**Ships with commit:** `v0.9.11: feat(pypi): the dazzle-git-repokit alias; docs: README and guides rewritten`
**Companion automated tests:** `tests/test_packaging.py` (8: the alias's own publish job, its lockstep with git-repokit), `tests/test_cli_examples.py` (3: every flag and language the CLI and the docs show exists; `repokit list` ends with the license catalogue), `tests/test_docs_links.py` (2: every relative link resolves; the README links every guide), `tests/test_license_adopt.py` (7: adopt and the project's own license), `tests/test_license_cli.py` (+1: `proprietary-evaluation`).

## What this is

0.9.11 publishes `dazzle-git-repokit`, an alias that installs git-repokit; stops `adopt` from asking for a license the project already has or the person has not chosen; adds the `proprietary-evaluation` license; makes `repokit list` show the license catalogue; respells "licence" and "colour" in US English (the `badge_types` key `colour` is now `color`); and rewrites the documentation. The tests check the workflow, the alias's metadata, adopt's license handling, the CLI's examples and the links. This checklist covers what only a real release, a real terminal and a real reader show.

## Prerequisites

1. For HV.1 and HV.2: the pending trusted publisher on PyPI for `dazzle-git-repokit` (owner DazzleTools, repository git-repokit, workflow `publish.yml`, environment `pypi`), this version pushed, and a v0.9.11 GitHub Release published.
2. For everything else: this checkout installed (`pip install -e .`), and a scratch folder. Never run these in a real project or with your real `~/.repokit/config.json` in play for Sections 2-3: name a config with `--config FILE`, which takes the project-config tier.
3. **Scratch git rules.** Every `git` command below carries `-C <scratch path>`, and every commit carries `-c user.email=t@example.com -c user.name=Tester -c commit.gpgsign=false -c tag.gpgsign=false`, so nothing lands in a real repository and no GPG prompt appears. Do not change global git config.
4. **A git identity for repokit's own commits.** Add `--user-name Tester --user-email t@example.com` to every `repokit create` and `repokit adopt` below unless you have a global git identity; without one, repokit asks for a name on stdin and its commits fail with "Author identity unknown". If your global config signs commits, set `GIT_CONFIG_COUNT=2 GIT_CONFIG_KEY_0=commit.gpgsign GIT_CONFIG_VALUE_0=false GIT_CONFIG_KEY_1=tag.gpgsign GIT_CONFIG_VALUE_1=false` in the shell first, or repokit's commits will prompt for a passphrase.
5. **One parent folder per adopt.** `adopt` uses the private-branch layout and checks `main` and `dev` out in folders beside the project (`../github`, `../dev`), so two adopted fixtures in one parent collide. Give every HV.3 and Section 1 fixture its own parent: `mkdir hv3 && cd hv3`, then the steps.

Make the scratch folder (pick your shell):

- [ ] **Steps:** in a fresh virtual environment on Python 3.10 or newer: `pip install dazzle-git-repokit`, then `repokit --version`. With pipx if you have it: `pipx install dazzle-git-repokit`, then `repokit --version`.

- [ ] **Why this matters:** pipx exposes only the named package's commands, which is why the alias declares `repokit` itself.

### HV.3 -- adopt keeps the project's own license, with no flag

- [ ] **Steps** (same in every shell after `cd` into the scratch folder):
  ```
  mkdir own-license
  git -C own-license init -q
  python -c "open('own-license/main.py','w').write('print(1)\n'); open('own-license/LICENSE.md','w').write('My terms.\n')"
  git -C own-license add -A
  git -C own-license -c user.email=t@example.com -c user.name=Tester -c commit.gpgsign=false commit -qm init

  ```
- [ ] **Expected:** adopt finishes without asking for a license; `LICENSE.md` still reads `My terms.`; no `LICENSE` appears; `.repokit.json` says `"license": "existing:LICENSE.md"`.
- [ ] **Why this matters:** adopt exists to fill gaps; asking for a license the project already has was the friction this version removes.

### HV.4 -- The README reads well on GitHub (MANUAL: network)

## Section 1: adopt and the license

### 1.1 No license file and nothing named

- [ ] **Steps:** as HV.3, but write no license file, in a folder `no-license`, with a config that names none: create `empty.json` containing `{}` in the scratch folder and run `repokit --config ../empty.json adopt . --no-push`. (The config tier stops your own `~/.repokit/config.json` from supplying a license only if it names none; if yours names `license`, expect 1.2's outcome instead.)
- [ ] **Expected:** a warning once: `No license found in the project and none named, so none was added; add a LICENSE file, or name one with --license <id>`; exit code 0; no `LICENSE`; `.repokit.json` says `"license": "none"`.
- [ ] **Check:** the warning is readable in your terminal (no mangled characters on cmd.exe).

### 1.2 No license file, the config names one

- [ ] **Steps:** as 1.1 with `lic.json` = `{"license": "mit"}` and `repokit --config ../lic.json adopt . --no-push`.
- [ ] **Expected:** `LICENSE` is the MIT text with your name and this year; `.repokit.json` says `"license": "mit"`.

### 1.3 An explicit `--license` replaces the project's own

- [ ] **Steps:** as HV.3 with `LICENSE` instead of `LICENSE.md`, then `repokit adopt . --license apache-2.0 --no-push`.
- [ ] **Expected:** `LICENSE` is now the Apache 2.0 text. `repokit adopt --help` says naming one replaces the project's own file.

### 1.4 The file's own name reaches the generated files

- [ ] **Steps:** as HV.3 (a `COPYING` file instead of `LICENSE.md`), adopted with `--language python`.
- [ ] **Expected:** if adopt wrote a `pyproject.toml`, its `license-files` line names `COPYING`; the README's License section, if written, links `COPYING`.

### 1.5 `create` still refuses

- [ ] **Steps:** `repokit --config empty.json create refused --no-push` (with a global config that names no license).
- [ ] **Expected:** `no license named: ...` with the catalogue, and no `refused/` folder.

## Section 3: the README's examples

### 3.1 The multi-branch loop

- [ ] **Steps** (from the scratch folder):
  ```
  repokit create my-app --branch-strategy standard --language python --license mit --no-push
  cd my-app/local
  python -c "import os; os.makedirs('private/claude', exist_ok=True); open('private/claude/note.md','w').write('secret\n'); open('parser.py','w').write('x = 1\n')"
  git -C . add -A
  git -C . add -f private/claude/note.md
  git -C . -c user.email=t@example.com -c user.name=Tester -c commit.gpgsign=false commit -qm "Add the parser"
  cd ../dev
  repokit safe-merge private --preview
  repokit safe-merge private
  git -C . -c user.email=t@example.com -c user.name=Tester -c commit.gpgsign=false commit -qm "Add the parser"
  cd ../github
  repokit safe-merge dev
  git -C . -c user.email=t@example.com -c user.name=Tester -c commit.gpgsign=false commit -qm "Release the parser"
  ```
- [ ] **Expected:** the preview lists `private/claude/` among the excluded paths; `parser.py` reaches `dev/` and `github/`; `private/` (the note `add -f` staged on the private branch, and the `instructions/` files create tracked there) and `CLAUDE.md` exist in neither: `git -C ../github ls-tree -r --name-only HEAD` shows no `private/` path.
- [ ] **Known defect (#16):** the create prints `fatal: ambiguous argument 'private': both revision and filename` once per public branch, and `dev/` and `github/` start with only README and `.github/`; the loop still delivers. Note whether it appears.
- [ ] **Check:** the "Safe merge completed" line renders (it carries a symbol that cp1252 consoles may show as `?`).

### 3.2 The comma `--with` examples

- [ ] **Steps:** `repokit create p1 --with claude-plugin,ts --license mit --no-push`; `repokit create p2 --with node,ts,node-package --license isc --no-push`; `repokit create p3 --with c-cpp/cmake-app,python/script --license mit --no-push`; `repokit create p4 --with script,ts --license mit --no-push`.
- [ ] **Expected:** p1 and p3 note "assembled from layers; not a tested preset"; p2's `.repokit.json` says `"archetype": "js-ts/node-package"`; p3 notes ".vscode/ holds c-cpp's debug configurations; python's were not merged in"; p4 is refused: `'script' is ambiguous: js-ts/script or python/script`.

### 3.3 `repokit analyze`'s suggestions

- [ ] **Steps:** make `a/` with an `app.py` and no LICENSE, and `b/` with an `app.py` and a `LICENSE`; `repokit analyze a`, `repokit analyze b`.
- [ ] **Expected:** both suggest `repokit adopt <dir> --migration-strategy safe` (never `--strategy`), with no `--license`.
