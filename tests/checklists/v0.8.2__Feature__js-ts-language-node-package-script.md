# Human Test Checklist: the `js-ts` language -- `node-package` and `script`

**Target version:** 0.8.2
**Ships with commit:** v0.8.2: feat(layers): the js-ts language -- node, ts, script, node-package (TBD until committed)
**Companion automated tests:** `tests/test_layers_js_ts.py` (the default package's tree, metadata and version-tool check; the script run with node and its `node:test` tests when node is on PATH; `script` as a build choice and the bare name's ambiguity; the planned flavours' refusals); the manifest and compositions tests cover the new entries (js-ts tries 16 combinations). What no automated test does: install packages from the network, so compiling the TypeScript package and publishing are yours.

## What this is

The language git-repokit's revival was started for. `--language js-ts` makes an npm package in TypeScript; `--with js-ts/script` makes a one-file script run with node. Four layers below the language are built (`node`, `ts`, `script`, `node-package`) and nine are announced. The version lives in `VERSION`; the vendored version tool keeps `package.json` in step. The shape follows a measure of the eleven Node checkouts on this machine (ES modules, npm, Vitest with Vite as the web stack, which a later version builds). What only you can judge: whether the package's `package.json` is what you would have written, whether compiling and running it feels right, and whether the floor's `.js` script is the right size.

## High-Value Verification (~6 minutes)

### HV.1 -- The default: an npm package in TypeScript

- [ ] **Steps:** in `SCRATCH`: `repokit create my-lib --language js-ts --no-push`; `dir my-lib` / `ls -a my-lib`; read `my-lib/package.json` and `my-lib/tsconfig.json`.
- [ ] **Expected:** `package.json` (name `my-lib`, version `0.1.0`, `"type": "module"`, `engines node >=20`, `exports` and `types` pointing into `dist/src/`, scripts `build`, `typecheck`, `test`, `prepublishOnly`, `typescript` as the only devDependency, no `"private"`); `tsconfig.json` strict, `outDir dist`, `include ["src", "tests"]`; `src/index.ts`, `tests/index.test.ts`, `VERSION`, `.editorconfig`, `.repokit-common.toml`, `.github/workflows/ci-js-ts.yml` and `release.yml`; `.gitignore` carries `node_modules/` and `dist/`; `.repokit.json` records `"archetype": "js-ts/node-package"` and `"layers": ["js-ts", "js-ts/node", "js-ts/ts", "js-ts/node-package"]`. **Judge:** is this the `package.json` you would write for a new library? Anything missing (a license field, `repository`, `keywords`, `sideEffects: false`)?

### HV.2 -- The version tool keeps `package.json`

- [ ] **Steps:** in `my-lib`: `python scripts/repokit-common/sync-versions.py --check`; edit `VERSION` to `0.1.1`; `python scripts/repokit-common/sync-versions.py`; read `package.json`'s version.
- [ ] **Expected:** `--check` exits 0; after the bump `package.json` says `0.1.1` (the extra target), the CHANGELOG's links move, `--check` exits 0 again.

### HV.3 -- The script floor, run with node

- [ ] **Steps:** `repokit create my-tool --with js-ts/script --no-push`; `node my-tool/my-tool.js --version`; `node my-tool/my-tool.js --help`; in `my-tool`: `npm test`.
- [ ] **Expected:** `my-tool.js`, `VERSION`, `package.json` (`"private": true`, `"test": "node --test"`), `tests/version.test.js`, no `tsconfig.json`, no `release.yml`; `--version` prints `0.1.0`; `--help` names the script; `npm test` runs the two `node:test` tests and passes with no install. **Judge:** the floor's size.

### HV.4 -- The facets at work

- [ ] **Steps:** `repokit create x --with script --no-push`; `repokit create y --language js-ts --with script --no-push`; `repokit create z --with js-ts/script,node-package --no-push`; `repokit list js-ts`.
- [ ] **Expected:** the first fails: `'script' is ambiguous: js-ts/script or python/script` (two languages have the floor now); the second resolves to `js-ts/script`; the third assembles (script is a build choice, node-package a purpose: different facets) and prints the one-line note that it is not a tested preset; `list js-ts` shows two built presets and five planned, and the facets `runtime one of: browser (planned), node`, `dialect one of: ts`, `build one of: script, vite (planned)`, `framework any of: ...`, `purpose one of: ...`.

### HV.5 -- The planned flavours refuse

- [ ] **Steps:** `repokit create p --with js-ts/claude-plugin --no-push`; `repokit create w --with js-ts/web-vite-react --no-push`.
- [ ] **Expected:** both fail before anything is created, naming the preset as not built yet with its description; the plugin's says 0.8.3.

## Section 1: compile, test, and the CI (needs network, ~5 min)

- [ ] **Steps:** in `my-lib`: `npm install`; `npm test`; `npm run build`; `node -e "import('./dist/src/index.js').then(m => console.log(m.greet('you')))"`.
- [ ] **Expected:** `npm install` fetches TypeScript only; `npm test` compiles then runs `node --test`, two tests pass; `dist/src/index.js` and `index.d.ts` exist; the import prints `Hello, you, from my-lib.` **Judge:** compile time, the `dist/src` layout (is `dist/` with `src/` under it acceptable, or should `rootDir` be `src` and the tests compiled elsewhere?).
- [ ] **Steps (optional, your own throwaway repository):** push `my-lib` and open Actions.
- [ ] **Expected:** `CI (JavaScript/TypeScript)` runs on ubuntu and windows for Node 20 and 22: install, type-check, test. `Publish to npm` does nothing until a release is published, and then needs an `NPM_TOKEN` secret.

## Section 2: the hooks on the first commit (~1 min)

- [ ] **Steps:** in `my-lib`: change `src/index.ts`, `git add -A && git commit -m "change"`.
- [ ] **Expected:** the pre-commit hook passes; the post-commit hook says nothing about a missing version file; `languages` are detected (javascript, typescript) without being written in `.repokit-common.toml`.

## What the automated tests DO cover

The created trees' shape and metadata, the settings' keys and the extra target, no tokens left, the version tool's `--check`, the script's run and its tests under node, the build-facet exclusivity and the bare-name ambiguity, the planned flavours' refusals, every composition of the built layers assembling cleanly.

## What mocks and automation DON'T cover

`npm install`, the TypeScript compile, the package import, the workflows on GitHub, the hooks' language detection on a real commit, the taste of `package.json`.

## Legend

- **preset** -- a named, tested list of layers (`js-ts/node-package`, `js-ts/script`).
- **facet** -- the question a layer answers: runtime, dialect, build, framework, purpose.
- **the floor** -- the simplest shape a language supports: one file, `VERSION`, no packaging.
- **the note** -- `Note: assembled from layers; not a tested preset (...)`.
