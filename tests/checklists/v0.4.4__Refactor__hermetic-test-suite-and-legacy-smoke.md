# Human Test Checklist: isolated test suite, two fixes, and the legacy smoke test

**Target version:** 0.4.4
**Ships with commit:** v0.4.4: test: isolate the suite; fix analyze and guardrails
**Companion automated tests:** 72 passed, 13 skipped (12 live GitHub tests, 1 by design), 1 expected failure -- including `tests/test_hermetic.py` (5), `tests/test_legacy_smoke.py` (5), and the previously failing `tests/test_guardrails.py` (7) and `tests/test_cli_integration.py` (18)

## What this is

The test suite used to run against the developer's own machine: it signed the commits it made, wrote to the real `~/.repokit/credentials.json`, and read a real GitHub token from `.env.test`, which let some tests create real repositories. It now runs isolated. Along the way two user-facing bugs were fixed (`repokit analyze` crashing after its report; `repokit setup-guardrails` failing on Windows), and a smoke test now pins the legacy branch layout that `repokit create --branch-strategy standard` produces. This checklist covers what the suite cannot see from inside itself: prompts on a real machine, the real home directory, and how the two fixed commands look in a terminal.

## Prerequisites

1. A checkout of git-repokit, with Python 3.8+ and `pip install -e ".[dev]"`.
2. Ideally a machine where `git config --global commit.gpgsign` is `true` -- that is what HV.1 checks.
3. A scratch directory outside the repo. Every step below works inside it.
4. **Before any step that runs `repokit create` or `repokit setup-guardrails` by hand**, turn signing off for that shell only, so repokit's own commits do not ask you to sign:

   **cmd.exe**
   ```cmd
   set GIT_CONFIG_COUNT=2
   set GIT_CONFIG_KEY_0=commit.gpgsign
   set GIT_CONFIG_VALUE_0=false
   set GIT_CONFIG_KEY_1=tag.gpgsign
   set GIT_CONFIG_VALUE_1=false
   ```
   **PowerShell**
   ```powershell
   $env:GIT_CONFIG_COUNT = "2"
   $env:GIT_CONFIG_KEY_0 = "commit.gpgsign"; $env:GIT_CONFIG_VALUE_0 = "false"
   $env:GIT_CONFIG_KEY_1 = "tag.gpgsign";    $env:GIT_CONFIG_VALUE_1 = "false"
   ```
   **POSIX**
   ```bash
   export GIT_CONFIG_COUNT=2 GIT_CONFIG_KEY_0=commit.gpgsign GIT_CONFIG_VALUE_0=false GIT_CONFIG_KEY_1=tag.gpgsign GIT_CONFIG_VALUE_1=false
   ```
   Never change your global git config for this; close the shell afterwards.

Reset between sections: delete the scratch directory's contents.

## High-Value Verification (~5 minutes)

### HV.1 -- The suite never asks you to sign anything

- [ ] **Steps** (a fresh shell, *without* the prerequisite 4 variables; same in every shell):
  ```
  python -m pytest -q
  ```
- [ ] **Expected:** `72 passed, 13 skipped, 1 xfailed` (or better). **No** Kleopatra / pinentry / GPG dialog appears at any point.
- [ ] **Why this matters:** the tests make dozens of throwaway commits; each used to raise a signing prompt on a machine that signs by default.

### HV.2 -- The real credentials file is never touched

- [ ] **Steps:** note whether `~/.repokit/credentials.json` exists, and its modified time, then run `python -m pytest -q`, then look again.

  **cmd.exe**: `dir %USERPROFILE%\.repokit` · **PowerShell**: `Get-Item $env:USERPROFILE\.repokit\credentials.json | Select LastWriteTime` · **POSIX**: `ls -l ~/.repokit/`
- [ ] **Expected:** unchanged -- still absent if it was absent, the same time if it existed. (`test_store_credentials` writes a dummy token; it must land in a temporary home.)
- [ ] **Why this matters:** that file holds a person's real GitHub token.

### HV.3 -- Live GitHub tests are opt-in

- [ ] **Steps:** `python -m pytest -q -rs` and read the skip reasons.
- [ ] **Expected:** 12 skips reading `live GitHub test; set REPOKIT_LIVE_GITHUB=1 to run`, even when `.env.test` exists with a token. Do **not** set the variable during this checklist.
- [ ] **Why this matters:** those tests create real repositories on the token's account.

### HV.4 -- `repokit analyze` finishes cleanly

- [ ] **Steps:** in the scratch directory, create a folder with one `main.py`, `cd` into it, and run `repokit analyze .`
- [ ] **Expected:** the analysis report, the NEXT STEPS block, exit code 0, and **no** `ERROR ... 'Namespace' object has no attribute 'publish_to'` line at the end.
- [ ] **Why this matters:** the command used to print a full report and then fail, so scripts saw an error.

### HV.5 -- Legacy layout and its guard, by hand

- [ ] **Steps** (prerequisite 4 set first), in the scratch directory:
  ```
  repokit create demo --branch-strategy standard --no-push
  git -C demo/local branch
  ```
  Then in `demo/github` create a file `CLAUDE.md`, `git -C demo/github add -f CLAUDE.md`, and `git -C demo/github commit -m test`.
- [ ] **Expected:** branches `dev`, `live`, `main`, `private`, `staging`, `test`, with `* private` in `local`; the commit in `github` (on `main`) is **refused** by "RepoKit Pre-Commit Check", and the message tells you how to proceed. Read it: is it clear?
- [ ] **Why this matters:** existing projects still live in this layout; the guard is what keeps private files off public branches.

## Section 1: Windows-specific

### 1.1 `repokit setup-guardrails` installs its hook (Windows)

- [ ] **Steps** (prerequisite 4 set): in a scratch folder, `git init`, commit one file (`git -C . -c commit.gpgsign=false commit -m init` after adding it), then `repokit setup-guardrails`.
- [ ] **Expected:** success, and `.git\hooks\pre-commit` exists. Before the fix this failed with a `'charmap' codec can't decode` error.
- [ ] **Check:** open the hook in an editor; its non-ASCII symbols (e.g. the magnifier in "RepoKit Pre-Commit Check") display correctly.

### 1.2 Hook output in the console

- [ ] **Steps:** repeat HV.5's refused commit in **cmd.exe** and in **PowerShell**.
- [ ] **Expected:** readable output in both; note any mojibake where the emoji are. (Cosmetic; record it, do not block on it.)

## What the automated tests DON'T cover

- A real signing prompt: the suite can only check git's configuration, not that no dialog appeared (HV.1).
- The real home directory: the suite runs inside a temporary one by design (HV.2).
- How the two fixed commands and the hook message read in cmd.exe and PowerShell (HV.4, 1.2).
- A machine **without** an editable install of git-repokit: here `python -m repokit` from a temporary folder works either way, so the suite cannot prove its `PYTHONPATH` setting is needed. On a fresh clone, run HV.1 before `pip install -e .` once.

## Reporting issues found

Note the step number, the exact command and output, your OS and shell, and file an issue that references this checklist.

## Cleanup

Delete the scratch directory. Close any shell where you set the prerequisite 4 variables (or unset them: `set GIT_CONFIG_COUNT=` / `Remove-Item Env:\GIT_CONFIG_COUNT` / `unset GIT_CONFIG_COUNT`).
