# Human Test Checklist: badge templates and the README ending

**Target version:** 0.9.7
**Ships with commit:** `v0.9.7: feat(readme): the house's badge templates and README ending`
**Companion automated tests:** `tests/test_badges.py` (10), `tests/test_readme_blocks.py` (15), `tests/test_github_owner.py` (6); full suite 293 passed, 14 skipped, 2 xfailed.

## What this is

0.9.7 writes the README's badge line and its ending the way the house's own projects do. The tests check the order, the members, the CI rule and the colours as text; only a person can see whether the line looks right on GitHub and whether seven badges really fill one row.

**Public:** `CHANGELOG.md` [0.9.7]; the house references `DazzleML/Claude-Session-Backup`, `DazzleTools/dazzlelink`, `DazzleNodes/ComfyUI-Smart-Resolution-Calc`.

**Project-private** (not in public git history, for project maintainers):

## Prerequisites

1. git-repokit 0.9.7 (`repokit --version`).
2. A short scratch folder, and unsigned commits for hand-run creates. Never change global git config.

   **cmd.exe**:
   ```cmd
   set GIT_CONFIG_COUNT=2
   set GIT_CONFIG_KEY_0=commit.gpgsign
   set GIT_CONFIG_VALUE_0=false
   set GIT_CONFIG_KEY_1=tag.gpgsign
   set GIT_CONFIG_VALUE_1=false
   mkdir %TEMP%\rkb & cd /d %TEMP%\rkb
   ```

   **PowerShell**:
   ```powershell
   $env:GIT_CONFIG_COUNT = "2"
   $env:GIT_CONFIG_KEY_0 = "commit.gpgsign"; $env:GIT_CONFIG_VALUE_0 = "false"
   $env:GIT_CONFIG_KEY_1 = "tag.gpgsign"; $env:GIT_CONFIG_VALUE_1 = "false"
   New-Item -ItemType Directory -Force "$env:TEMP\rkb" | Out-Null; Set-Location "$env:TEMP\rkb"
   ```

   **POSIX**:
   ```bash
   export GIT_CONFIG_COUNT=2 GIT_CONFIG_KEY_0=commit.gpgsign GIT_CONFIG_VALUE_0=false GIT_CONFIG_KEY_1=tag.gpgsign GIT_CONFIG_VALUE_1=false
   mkdir -p /tmp/rkb && cd /tmp/rkb
   ```
3. Each create below goes in its own subfolder name, so nothing collides.

## High-Value Verification (~10 minutes)

### HV.1 -- The PyPI line reads like Claude-Session-Backup's

- [ ] **Steps** (same in every shell): `repokit create rkb-pypi --language python --license gpl-3.0-or-later --extras all --no-push`, then open `rkb-pypi/README.md` in a Markdown preview (VS Code: Ctrl+Shift+V), or push it to a throwaway and open it on GitHub.
- [ ] **Expected:**
  - PyPI, Release Date, PyPI Downloads, CI, Python 3.10+, License: GPL v3 (green), GitHub Discussions, Installs, Platform -- in that order, Platform last.
  - Judge: do the colours sit well side by side?
- [ ] **Why this matters:** the badge line is the first thing a visitor sees, and it is meant to match the house's own projects.

### HV.2 -- Seven badges fill one row

- [ ] **Steps:** look at HV.1's line, and at `repokit create rkb-js --language js-ts --license mit --extras all --no-push` (seven badges with CI).
- [ ] **Expected:**
  - The js-ts line fits one row.
  - The PyPI line wraps once, with CI on the first row and the last badges on the second.
  - If a row holds a different number, note it: the rule's row width (7) is a setting to tune.
- [ ] **Why this matters:** CI is a filler that is meant never to start a row alone.

### HV.3 -- The README ends with License, and credits nobody but others

- [ ] **Steps:** read the end of `rkb-pypi/README.md`.
- [ ] **Expected:**
  - `## Contributing` with "See **CONTRIBUTING.md** for:" and four items.
  - No `## Acknowledgements`.
  - `## License` last: "rkb-pypi, Copyright (C) <year> <your git name>" and "Licensed under the GNU General Public License v3.0 or later (GPL-3.0-or-later) -- see LICENSE".
  - The support button appears only with `--github` (it needs your login).
- [ ] **Why this matters:** the 0.9.5 README credited the project's own author below the licence.

### HV.4 -- Choosing a template, a list, and your own

- [ ] **Steps:**
  1. `repokit create rkb-min --language python --license mit --badges minimal --no-push`
  2. `repokit create rkb-list --language python --license mit --badges platform,license,python --no-push`
  3. Add a template of your own to `~/.repokit/config.json` (back the file up first), e.g. `"badge_templates": {"mine": ["python", "license", "platform"]}`, then `repokit create rkb-mine --language python --license mit --badges mine --no-push`.
- [ ] **Expected:**
  1. Python, License.
  2. Python, License, Platform (sorted into the house order whatever order you typed).
  3. Your three badges.
- [ ] **Why this matters:** templates are how you avoid editing the badge line by hand on every project.
