# Human Test Checklist: v0.9.1 -- the Python Claude-plugin shape, the shared plugin layer, the second-language hint

**Target version:** 0.9.1
**Ships with commit:** `v0.9.1: feat(layers): python/claude-plugin, a shared plugin layer, the second-language hint` (TBD until committed)
**Companion automated tests:** 11 in `tests/test_layers_claude_plugin.py` (one a strict xfail), plus changed expectations in `tests/test_layers.py`, `tests/test_layers_js_ts.py`, `tests/test_layers_compositions.py`.

## What this is

v0.9.1 lets a Claude Code plugin be written in Python as well as JavaScript/TypeScript, keeps the files both shapes share in one place, says out loud when a second language gets no preset, and makes a JavaScript/TypeScript project's push run its own tests. The automated tests prove the resolver and the created trees; this checklist covers what only a person can see: the plugin actually installed into Claude Code, the hook firing in a real session, the Windows Python lookup, and how the notes read at a terminal.

## Prerequisites

1. Windows 10/11 with Git for Windows, Python 3.10+, Node 20+ with npm, Claude Code installed.
2. A scratch folder, a license for the creates, an unsigned git identity, the sibling git-repokit-common checkout as the vendoring source. Set once per shell:

   **cmd.exe**:
   ```cmd
   set SCRATCH=%TEMP%\rk091
   mkdir %SCRATCH%
   set REPOKIT_LICENSE=mit
   set GIT_CONFIG_COUNT=2
   set GIT_CONFIG_KEY_0=commit.gpgsign
   set GIT_CONFIG_VALUE_0=false
   set GIT_CONFIG_KEY_1=tag.gpgsign
   set GIT_CONFIG_VALUE_1=false
   set REPOKIT_COMMON_SOURCE=C:\code\git-repokit-common
   cd /d %SCRATCH%
   ```

   **PowerShell**:
   ```powershell
   $env:SCRATCH = "$env:TEMP\rk091"; New-Item -ItemType Directory -Force $env:SCRATCH | Out-Null
   $env:REPOKIT_LICENSE = "mit"
   $env:GIT_CONFIG_COUNT = "2"; $env:GIT_CONFIG_KEY_0 = "commit.gpgsign"; $env:GIT_CONFIG_VALUE_0 = "false"
   $env:GIT_CONFIG_KEY_1 = "tag.gpgsign"; $env:GIT_CONFIG_VALUE_1 = "false"
   $env:REPOKIT_COMMON_SOURCE = "C:\code\git-repokit-common"
   Set-Location $env:SCRATCH
   ```

   **POSIX (Git Bash)**:
   ```bash
   export SCRATCH=/tmp/rk091; mkdir -p "$SCRATCH"; cd "$SCRATCH"
   export REPOKIT_LICENSE=mit REPOKIT_COMMON_SOURCE=/c/code/git-repokit-common
   export GIT_CONFIG_COUNT=2 GIT_CONFIG_KEY_0=commit.gpgsign GIT_CONFIG_VALUE_0=false GIT_CONFIG_KEY_1=tag.gpgsign GIT_CONFIG_VALUE_1=false
   ```

   Run every create with stdin closed (`< NUL` in cmd.exe, `< /dev/null` in bash) and `--no-push`.
3. **Reset between sections:** delete the created folders in the scratch directory. Remove an installed test plugin from Claude Code with `/plugin uninstall <name>` and `/plugin marketplace remove <name>`.

## High-Value Verification (~10 minutes)

### HV.1 -- The Python plugin installs and its hook fires

Validates: the whole Python shape, end to end, in Claude Code itself.

- [ ] **Steps:**
  1. `repokit create py-plug --language python --with claude-plugin --description "A demo" --no-push < NUL`
  2. Set the plugin's debug variable (the project name upper-snake plus `_DEBUG`), then start Claude Code from a different folder: cmd `set PY_PLUG_DEBUG=1`, PowerShell `$env:PY_PLUG_DEBUG = "1"`, bash `export PY_PLUG_DEBUG=1`.
  3. In Claude Code: `/plugin marketplace add %SCRATCH%\py-plug` then `/plugin install py-plug@py-plug`, then start a new session.
- [ ] **Expected:** the session's context carries `py-plug saw a SessionStart event (source: startup).` (ask Claude what context it was given at start, or watch the hook output with `claude --debug`).
- [ ] **Why this matters:** a plugin that only passes its own tests but never fires in Claude Code is not a plugin.

### HV.2 -- The js-ts plugin still installs and fires the same way

- [ ] **Steps:** as HV.1 with `repokit create js-plug --language js-ts --with claude-plugin ...` and `JS_PLUG_DEBUG=1`.
- [ ] **Expected:** the same line, from `js-plug`. Compare `plugin\README.md`, `plugin\.claude-plugin\plugin.json` and `.claude-plugin\marketplace.json` between the two projects: identical apart from the names.
- [ ] **Why this matters:** the shared layer must not have changed what the js-ts plugin gives (it is byte-for-byte 0.9.0's).

### HV.3 -- The bare name, by language

- [ ] **Steps:** `repokit create a --with claude-plugin --no-push < NUL`; `repokit create b --language python --with claude-plugin --no-push < NUL`; `repokit create c --language python,js-ts --with claude-plugin --no-push < NUL`.
- [ ] **Expected:** `a` is the js-ts plugin (has `package.json`); `b` the Python one (has `plugin\hooks\scripts\session_start.py`, no `package.json`); `c` refuses with `'claude-plugin' is ambiguous: js-ts/claude-plugin or python/claude-plugin` and no `any/` in the message, and leaves no folder.
- [ ] **Why this matters:** js-ts stays the default for a bare name; the Python shape is there when asked for.

### HV.4 -- The second-language note reads well

- [ ] **Steps:** `repokit create duo --language python,js-ts --no-push < NUL`.
- [ ] **Expected:** one line `Note: js-ts got no preset of its own; add --with js-ts/<name> (see `repokit list js-ts`)`; the project has the Python package and only the js-ts language layer. Judge the wording: does it tell a newcomer what to type next?

### HV.5 -- A js-ts project's push runs its tests

- [ ] **Steps:** in `js-plug`, run the vendored hook as a push would (Git Bash): `printf 'refs/heads/main %s refs/heads/main %040d\n' $(git rev-parse HEAD) 0 | bash scripts/repokit-common/hooks/pre-push origin x`.
- [ ] **Expected:** `Product languages: javascript`; `Running tests...` then `> js-plug@0.1.0 test` / `> node --test` and the node test results; `Pre-push validation complete`. No `tests/test_*.py` line.
- [ ] **Why this matters:** before 0.9.1 a js-ts project's push ran no tests at all.

## Section 1: the push, by project shape

### 1.1 The TypeScript default before and after `npm install`
- [ ] **Steps:** `repokit create ts-app --language js-ts --no-push < NUL`; run the hook as in HV.5; then `npm install` in `ts-app` and run it again.
- [ ] **Expected:** first run prints `dependencies not installed: run npm install and the push will run npm test` and passes; second run compiles (`tsc -p .`) and runs `node --test`.

### 1.2 The Python plugin's push
- [ ] **Steps:** in `py-plug`, run the hook as in HV.5.
- [ ] **Expected:** `Product languages: python`; `test-command: python -m pytest plugin/tests -q` and four tests passing (one skipped if node is missing); no `No Python package directory` warning.

### 1.3 The Python line that remains (expected)
- [ ] **Steps:** look at HV.5's output.
- [ ] **Expected:** `Checking Python syntax...` / `[OK] Python syntax check passed` still appear. They come from git-repokit-common 0.4.1, which checks its own vendored `.py` files in every project; a repokit-common change is pending a decision. Record whether it bothers you in practice.

## Section 2: the Windows Python lookup
- [ ] **Steps:** in `py-plug`, run `node plugin\hooks\scripts\run-hook.mjs session_start.py < NUL` (cmd) / `node plugin/hooks/scripts/run-hook.mjs session_start.py < /dev/null` (bash).
- [ ] **Expected:** prints `{}` and exits 0. On a box where only the `py` launcher exists (no `python` or `python3` on PATH), the same works through `py`; with no Python at all it prints `[py-plug] Python 3 not found ...` on stderr and still exits 0.

## Section 3: what `repokit list` shows
- [ ] **Steps:** `repokit list`; `repokit list python`.
- [ ] **Expected:** no `any:` section anywhere; `python` shows `python/claude-plugin` among its presets and `claude-plugin` under `purpose`.
