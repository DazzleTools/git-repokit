## What this is

0.10.0 adds three things:
- **Paradox game mods** (`--language paradox`).
- **A written `languages` setting** in every created project.
- **`convos/`, `revisions/` and `logs/` inside the vault** (`private/`) instead of the project root.

This checklist creates real projects in a throwaway folder, and covers the one thing no test can: a game loading the mod.

## Prerequisites

1. git-repokit from this checkout (`pip install -e .`, or `python -m repokit`), git, Python 3.11+.
2. A fenced scratch folder, outside any git repository. Every create runs with signing off, so no GPG prompt appears, and with stdin closed:

   **cmd.exe**:
   ```cmd
   mkdir %TEMP%\rk010 && cd /d %TEMP%\rk010
   set GIT_CEILING_DIRECTORIES=%TEMP%
   set GIT_CONFIG_COUNT=2& set GIT_CONFIG_KEY_0=commit.gpgsign& set GIT_CONFIG_VALUE_0=false& set GIT_CONFIG_KEY_1=tag.gpgsign& set GIT_CONFIG_VALUE_1=false
   git rev-parse --show-toplevel
   ```
   **PowerShell**:
   ```powershell
   New-Item -ItemType Directory -Force "$env:TEMP\rk010" | Out-Null; Set-Location "$env:TEMP\rk010"
   $env:GIT_CEILING_DIRECTORIES = $env:TEMP
   $env:GIT_CONFIG_COUNT = 2; $env:GIT_CONFIG_KEY_0 = "commit.gpgsign"; $env:GIT_CONFIG_VALUE_0 = "false"; $env:GIT_CONFIG_KEY_1 = "tag.gpgsign"; $env:GIT_CONFIG_VALUE_1 = "false"
   git rev-parse --show-toplevel
   ```
   **POSIX**:
   ```bash
   mkdir -p "${TMPDIR:-/tmp}/rk010" && cd "${TMPDIR:-/tmp}/rk010"
   export GIT_CEILING_DIRECTORIES="$(dirname "$PWD")" GIT_CONFIG_COUNT=2 GIT_CONFIG_KEY_0=commit.gpgsign GIT_CONFIG_VALUE_0=false GIT_CONFIG_KEY_1=tag.gpgsign GIT_CONFIG_VALUE_1=false
   git rev-parse --show-toplevel
   ```
   - [ ] **Expected:** `fatal: not a git repository`. If it prints a path, stop: the folder is inside a repository.
3. Every git command below names its repository with `-C <project>`. Never change global git config.

**Reset between items:** each item creates its own project; delete the scratch folder at the end.

## High-Value Verification (~10 minutes; HV.3 needs the game)

### HV.1 -- a CK3 mod, laid out right

- [ ] **Steps:** `repokit create my-mod --language paradox --license none --no-push < NUL`. Use `< /dev/null` on POSIX. On PowerShell, omit the redirect: the create asks nothing.
- [ ] **Expected:**
  - `my-mod/mod/` holds exactly `descriptor.mod`, `localization/english/my_mod_l_english.yml` and `thumbnail.png`.
  - The localization file starts with a BOM: `python -c "print(open('my-mod/mod/localization/english/my_mod_l_english.yml','rb').read(3))"` prints `b'\xef\xbb\xbf'`.
  - `my-mod/.repokit-common.toml` has `languages = ["paradox"]`, `paradox-game = "ck3"`, and an extra target on `mod/descriptor.mod` with a `pattern`.
  - There is **no** `convos/`, `revisions/` or `logs/` at `my-mod/`; all three are in `my-mod/private/`.
  - `git -C my-mod/private ls-files` lists `convos/.gitkeep` and `revisions/.gitkeep`, and nothing under `logs/`.
- [ ] **Why this matters:** a Workshop upload ships `mod/` whole. Anything else in it, or a localization file without its BOM, breaks the mod.

### HV.2 -- the descriptor follows the version

- [ ] **Steps:** from `my-mod`, run `python scripts/repokit-common/sync-versions.py --bump patch`, then `git -C . diff -- mod/descriptor.mod`.
- [ ] **Expected:** one line changes, `version="0.1.0"` → `version="0.1.1"`. `supported_version` is unchanged, and `VERSION` reads `0.1.1`.
- [ ] **Why this matters:** hand-edited descriptor versions drift. The tool must touch only that line.

### HV.3 -- MANUAL: the game loads it

- [ ] **Steps:**
  - Write `Documents\Paradox Interactive\Crusader Kings III\mod\my-mod.mod` by hand, with the three lines `name="my-mod"`, `path="C:/.../rk010/my-mod/mod"` (forward slashes) and `supported_version="1.20.*"`.
  - Start the CK3 launcher and enable "my-mod" in a playset.
  - Start the game.
- [ ] **Expected:** the mod is listed, enables, and the game starts with it, with no new mod errors for it in `Documents\Paradox Interactive\Crusader Kings III\logs\error.log`.
- [ ] **Afterwards:** delete the pointer `my-mod.mod` and remove the mod from the playset. Never touch the launcher's own files.
- [ ] **Why this matters:** it's the purpose of the feature, and only the game can confirm it.

### HV.4 -- every create names its languages

- [ ] **Steps:** `repokit create p --with js-ts/claude-plugin --license none --no-push`, then `repokit create d --language python,js-ts --license none --no-push`. Add the same stdin redirect as in HV.1.
- [ ] **Expected:** `p/.repokit-common.toml` has `languages = ["javascript"]`. `d/pyproject.toml`'s `[tool.repokit-common]` has `languages = ["python", "javascript"]`.
- [ ] **Why this matters:** a plugin with its files in `plugin/` used to read as Python to the hooks.

### HV.5 -- the catalogue

- [ ] **Steps:** run `repokit list`, then `repokit list paradox`, then `repokit create x --with paradox/clausewitz,paradox/ck3 --license none --no-push`.
- [ ] **Expected:**
  - the overview fits one screen (40 lines or fewer), with one `planned:` line per language;
  - `repokit list paradox` names each planned game with its description;
  - the create is refused with `'clausewitz' and 'jomini' are both a dialect for paradox; pick one`, and makes no `x/`.
- [ ] **Why this matters:** the catalogue is how a person finds the presets.

## Section 1: the rest

### 1.1 The generic engine presets

- [ ] `repokit create j --with paradox/jomini ...` and `repokit create c --with paradox/clausewitz ...` give `mod/localization/` and `mod/localisation/` respectively. The descriptor says `supported_version="*"` with a comment to set it. The settings have `languages = ["paradox"]` and only a commented `paradox-game` hint.

### 1.2 The directory profiles follow the vault layout

- [ ] `repokit create s --dir-profile standard --license none --no-push` makes no `convos/`, `logs/` or `revisions/` at `s/`; they are in `s/private/`.

### 1.3 Optional: Tiger on push

- [ ] With `ck3-tiger` on PATH, add a bare local remote and push `my-mod`:
  - `git init --bare ../my-mod.git`
  - `git -C my-mod remote add origin ../my-mod.git`
  - `git -C my-mod push -u origin main`

  **Expected:** one summary line, `[OK] ck3-tiger: fatal: 0, error: 0, ...`, and `full report: .../.git/repokit-ck3-tiger.txt`. The push lands.

## What the automated tests DON'T cover

- **The game loading the mod (HV.3),** and the launcher's view of it.
- **The real Tiger.** git-repokit-common's tests stub it; its 0.4.3 checklist covers the real one.

## Reporting issues found

Note the item, the exact command and its output, and keep the scratch project. File an issue in DazzleTools/git-repokit naming this checklist and 0.10.0.

## Cleanup

1. Delete the CK3 pointer file if you made one (HV.3).
2. Delete the scratch folder:
   - **cmd.exe:** `cd /d %TEMP% && rmdir /s /q %TEMP%\rk010`
   - **PowerShell:** `Set-Location $env:TEMP; Remove-Item -Recurse -Force "$env:TEMP\rk010"`
   - **POSIX:** `cd / && rm -rf "${TMPDIR:-/tmp}/rk010"`
3. Clear `GIT_CEILING_DIRECTORIES` and the `GIT_CONFIG_*` variables, or close the shell.
