# Human Test Checklist: the private-branch create, fixed safely

**Target version:** 0.9.12
**Ships with commit:** `v0.9.12: fix(create): the private-branch strategies build real public branches, safely`
**Companion automated tests:** `tests/test_private_branch_create.py` (22), `tests/test_layers.py` (2 new), `tests/test_new_default.py` (1 new); mutation sweeps `tests/mutation/v0.9.12__sweep__private-branch-create.md` (10 killed, 3 equivalent) and `v0.9.12__sweep__common-kit-union.md` (12 killed).

## What this is

Before 0.9.12, `repokit create` with a private-branch strategy (standard, simple, gitflow, github-flow, minimal) built public branches that held only the initial commit, and still exited 0: `git reset --hard private` failed with "ambiguous argument 'private': both revision and filename", because a `private/` folder sits beside the `private` branch. 0.9.12 cuts each public branch from `refs/heads/<private branch>`. It also makes three things safe that the broken reset had been hiding, because they ran only after it. The cleanup that followed it now leaves the working folder alone, since `local/` is the person's private checkout. The `.github` step runs git only in the default branch's real worktree, never in a repository enclosing the project. A public branch that cannot be built now fails the create. This checklist runs the real command in throwaway folders and looks at what the tests cannot: the branches as a person sees them, the output, and the exit code in each shell.

## Prerequisites

**Safety first.** The fix is about `git reset --hard` and file deletion. Run every step in a throwaway folder that is **not inside any git repository**, never in a real project. On some machines `%TEMP%` is itself inside a home-directory repository, so the setup below fences git in with `GIT_CEILING_DIRECTORIES` and then proves the fence holds.

1. A checkout of git-repokit at 0.9.12 (this example uses `C:\code\git-repokit`; replace it with yours). Either `pip install -e <checkout>` or point `PYTHONPATH` at it, as below.
2. git on PATH. No GitHub login is needed (`--no-push`).
3. Set up the scratch folder, the git fence, and unsigned commits (some machines sign every commit, which would prompt for a passphrase on each one):

   **cmd.exe**:
   ```cmd
   set RK_SCRATCH=%TEMP%\rk0912-check
   mkdir %RK_SCRATCH%
   set GIT_CEILING_DIRECTORIES=%TEMP%
   set GIT_CONFIG_COUNT=2
   set GIT_CONFIG_KEY_0=commit.gpgsign
   set GIT_CONFIG_VALUE_0=false
   set GIT_CONFIG_KEY_1=tag.gpgsign
   set GIT_CONFIG_VALUE_1=false
   set PYTHONPATH=C:\code\git-repokit
   cd /d %RK_SCRATCH%
   git rev-parse --show-toplevel
   python -m repokit --version
   ```

   **PowerShell**:
   ```powershell
   $env:RK_SCRATCH = "$env:TEMP\rk0912-check"
   New-Item -ItemType Directory -Force $env:RK_SCRATCH | Out-Null
   $env:GIT_CEILING_DIRECTORIES = $env:TEMP
   $env:GIT_CONFIG_COUNT = "2"
   $env:GIT_CONFIG_KEY_0 = "commit.gpgsign"; $env:GIT_CONFIG_VALUE_0 = "false"
   $env:GIT_CONFIG_KEY_1 = "tag.gpgsign";    $env:GIT_CONFIG_VALUE_1 = "false"
   $env:PYTHONPATH = "C:\code\git-repokit"
   Set-Location $env:RK_SCRATCH
   git rev-parse --show-toplevel
   python -m repokit --version
   ```

   **POSIX**:
   ```bash
   export RK_SCRATCH="${TMPDIR:-/tmp}/rk0912-check"
   mkdir -p "$RK_SCRATCH"
   export GIT_CEILING_DIRECTORIES="$(dirname "$RK_SCRATCH")"
   export GIT_CONFIG_COUNT=2
   export GIT_CONFIG_KEY_0=commit.gpgsign GIT_CONFIG_VALUE_0=false
   export GIT_CONFIG_KEY_1=tag.gpgsign GIT_CONFIG_VALUE_1=false
   export PYTHONPATH=/path/to/git-repokit
   cd "$RK_SCRATCH"
   git rev-parse --show-toplevel
   python -m repokit --version
   ```

- [ ] **Expected:** `git rev-parse --show-toplevel` fails with `fatal: not a git repository`. **If it prints a path instead, stop: the scratch folder is inside a repository.** `repokit --version` prints 0.9.12.

**Reset between sections:** each section uses its own subfolder (`s1-standard`, `s4-outer`, ...), so no reset is needed. To start over, delete `%RK_SCRATCH%` (see Cleanup).

**The create command** used below, called `CREATE <strategy> [flags]` for short, is the same in every shell (run it from the section's own subfolder):

```
python -m repokit create p --language python --license mit --no-push --branch-strategy <strategy> [flags]
```

It should not prompt for anything. If it waits for input, note it as a finding and answer `n`.

**Exit code after a command:** cmd.exe `echo %ERRORLEVEL%`, PowerShell `$LASTEXITCODE`, POSIX `echo $?`.

## High-Value Verification (~5 minutes)

### HV.1 -- the standard strategy builds real public branches

Validates: public branches are cut from the private branch (`refs/heads/private`), not left at the initial commit.

- [ ] **Steps** (from `%RK_SCRATCH%\hv1`, an empty subfolder):
  1. `CREATE standard`, then read the exit code.
  2. `git -C p/local for-each-ref --format="%(refname:short) %(objectname:short) %(subject)" refs/heads`
  3. `git -C p/local ls-tree -r --name-only refs/heads/main`
- [ ] **Expected:** exit code 0. Branches `private`, `main`, `dev`, `staging`, `test`, `live`. `main` lists the project's files (`README.md`, `pyproject.toml`, the package, `.github/`...), not just one or two files. The create's output contains no `ambiguous argument` and no `ERROR` line.
- [ ] **Why this matters:** this was the bug: every public branch held only the initial commit, and the command said it succeeded.

### HV.2 -- nothing private reaches a public branch

- [ ] **Steps:** in the same project, for each public branch: `git -C p/local ls-tree -r --name-only refs/heads/<branch>` (pipe through `findstr /R "^private/ ^CLAUDE.md"` in cmd.exe, `Select-String '^(private/|CLAUDE\.md)'` in PowerShell, `grep -E '^(private/|CLAUDE\.md)'` in POSIX).
- [ ] **Expected:** no output for any public branch. `refs/heads/private` does list `private/...` and `CLAUDE.md`.
- [ ] **Why this matters:** the private branch is the only source. The `private/` folder never reaches a public branch.

### HV.3 -- the private checkout keeps its files

- [ ] **Steps:** in the same project, list `p/local` (`dir p\local /a`, `Get-ChildItem p/local -Force`, `ls -la p/local`), then `git -C p/local status --short` and `git -C p/local branch --show-current`.
- [ ] **Expected:** `p/local` is on `private`, `git status` is clean, and `private/`, `CLAUDE.md` and the project files are all on disk.
- [ ] **Why this matters:** the cleanup that used to follow the reset deleted files matching `.env*`, `*.log`, `logs/*`, `*.bak` from this folder, which is the person's own checkout. 0.9.12 never deletes from it. (Planting files *during* a create is covered by the automated test `test_files_in_the_private_working_folder_survive_the_public_branches`; it cannot be done by hand.)

### HV.4 -- a create inside another repository leaves it alone

- [ ] **Steps:** make a dummy enclosing repository inside the scratch folder and create inside it:
  1. `git init -q -b main %RK_SCRATCH%\hv4-outer` (PowerShell `"$env:RK_SCRATCH\hv4-outer"`, POSIX `"$RK_SCRATCH/hv4-outer"`), then add one file and commit it with `git -C <outer> -c user.name=T -c user.email=t@example.com -c commit.gpgsign=false commit -qm outer`.
  2. Note `git -C <outer> rev-parse HEAD`.
  3. From `<outer>\work`: `CREATE minimal`.
  4. `git -C <outer> rev-parse HEAD`, `git -C <outer> diff --cached --name-only`, `git -C <outer> log --oneline -3`.
- [ ] **Expected:** exit code 0. HEAD unchanged; nothing staged; no "Add GitHub configuration files" commit in the outer log. There is no `work\p\github` folder.
- [ ] **Why this matters:** before 0.9.12 the `.github` step ran `git add`/`git commit` in a `<name>/github` folder with no worktree in it. Git walked up and committed into whatever repository enclosed the project.

### HV.5 -- every private-branch strategy

- [ ] **Steps:** in one new subfolder per strategy (`hv5-simple`, `hv5-gitflow`, `hv5-github-flow`, `hv5-minimal`): `CREATE <strategy>`, read the exit code, list the branches as in HV.1, and run the HV.2 check.
- [ ] **Expected:** exit 0 each time; each public branch holds the project's files and nothing private; no `ambiguous argument`, no `ERROR`.

## Section 1: output and exit codes

### 1.1 What a successful create says

- [ ] **Steps:** re-read the output of HV.1.
- [ ] **Expected:** the lines about creating and verifying each public branch read clearly. A `WARNING` about no GitHub login (`YOUR_GITHUB_USERNAME`) is expected with `--no-push` and no configured login. Note anything confusing, too long or alarming.

### 1.2 Exit code in each shell

- [ ] **Steps:** after any successful create, read the exit code in cmd.exe, PowerShell and a POSIX shell (Git Bash counts).
- [ ] **Expected:** 0 in all three. (A failed public branch now gives non-zero. Forcing one needs a code hook, so the automated tests `test_a_public_branch_that_cannot_be_built_fails_the_create` and `..._fails_verification_...` cover it.)

## Section 2: worktree layouts

### 2.1 simple with the main branch in its own folder

- [ ] **Steps:** in a dummy enclosing repository made as in HV.4 (`s2-outer`), from `<outer>\work`: `CREATE simple --branch-dir-main public`. Then `git -C work/p/local worktree list`.
- [ ] **Expected:** exit 0; the worktree list shows `main` checked out at `work/p/public`; `work/p/public/.github/` exists; the outer repository's HEAD and index are unchanged.

### 2.2 The main worktree opens normally

- [ ] **Steps:** open `work/p/public` from 2.1 in your editor (VS Code: File > Open Folder).
- [ ] **Expected:** the editor sees a git repository on branch `main`, not the outer repository. Its source-control view shows no changes.

### 2.3 A private branch with another name

- [ ] **Steps:** in a new subfolder: `CREATE standard --private-branch scratch`, then list branches as in HV.1.
- [ ] **Expected:** exit 0; branches include `scratch` and the public branches, which hold the project's files; no `ambiguous argument`.

## Section 3: paths and line endings

### 3.1 A scratch path with a space

- [ ] **Steps:** repeat HV.1 from a subfolder named `with space` (quote the path in every command).
- [ ] **Expected:** the same result as HV.1.

### 3.2 core.autocrlf=true

- [ ] **Steps:** with `GIT_CONFIG_COUNT=3`, `GIT_CONFIG_KEY_2=core.autocrlf`, `GIT_CONFIG_VALUE_2=true` added to the environment (each shell's syntax as in Prerequisites), repeat HV.1 in a new subfolder; then `git -C p/local status --short`.
- [ ] **Expected:** the same branches and trees as HV.1; `git status` clean (no files shown as modified only by line endings).

## Section 4: the guards on the public branches

These need git-repokit-common 0.4.2 or later (`--with-common` vendors its current `main`).

### 4.1 A Python project's settings carry the private entries

- [ ] **Steps:** in a new subfolder: `CREATE simple --with-common`, then view `p/github/pyproject.toml` (cmd.exe `type`, PowerShell `Get-Content`, POSIX `cat`) and find `private-patterns` under `[tool.repokit-common]`.
- [ ] **Expected:** the list holds the layer's own entries (`"private/"`, `"local/"`, `".env"`) **and** `"CLAUDE.md"`, `"convos/"`, `"logs/"`, `"revisions/"`.

### 4.2 CLAUDE.md is refused on main, from its worktree

- [ ] **Steps:** in `p/github` (the `main` worktree from 4.1): create `CLAUDE.md`, `git -C p/github add -f CLAUDE.md`, then `git -C p/github -c user.name=T -c user.email=t@example.invalid -c commit.gpgsign=false commit -m try`.
- [ ] **Expected:** `COMMIT BLOCKED` naming `CLAUDE.md`, non-zero exit. Then `git -C p/github reset -q HEAD CLAUDE.md` and delete the file.

### 4.3 Removing a private file from a public branch is allowed

- [ ] **Steps:** in a project from HV.1 (no `--with-common`, so git-repokit's own guard is installed), in `p/github` on `main`:
  1. **Plant the fixture** (the guard refuses this by design, so this one commit runs with an empty hooks folder, and only in this scratch project): make an empty folder `nohooks` in the scratch folder, create `p/github/old.bak`, `git -C p/github add -f old.bak`, then `git -C p/github -c core.hooksPath=<absolute path of nohooks> -c user.name=T -c user.email=t@example.invalid -c commit.gpgsign=false commit -qm plant`.
  2. **The check, with the guard on:** `git -C p/github rm -q old.bak`, then `git -C p/github -c user.name=T -c user.email=t@example.invalid -c commit.gpgsign=false commit -m "remove old.bak"`.
- [ ] **Expected:** step 2's commit goes through. Before 0.9.12 the guard refused it as if `old.bak` were being added.

## What the automated tests DON'T cover

- How the output reads to a person, and whether its warnings alarm.
- The exit code as each real shell reports it.
- Paths with spaces, and `core.autocrlf=true`, on a real machine.
- An editor opening the main worktree (2.2).
- Machines with commit signing on, where any stray commit would prompt for a passphrase.
- Known and separate: the created project's pre-commit hook treats a deleted file as an added one, so a commit that removes a private-pattern file from a public branch is refused (the xfail above; a follow-up issue).

## Reporting issues found

1. Note the section and step.
2. Capture the exact command and its full output, and the exit code.
3. Keep the scratch subfolder (don't delete it) and note its path.
4. File an issue referencing this checklist and 0.9.12; link #16 when it is about the private-branch create.

## Cleanup

Delete the scratch folder. Nothing outside it was written.

- **cmd.exe:** `rmdir /s /q %RK_SCRATCH%`
- **PowerShell:** `Remove-Item -Recurse -Force $env:RK_SCRATCH`
- **POSIX:** `rm -rf "$RK_SCRATCH"`

(Where `dz safedel` is installed, `dz safedel <path>` is the recoverable choice.) Then clear the variables set in Prerequisites, or close the shell.
