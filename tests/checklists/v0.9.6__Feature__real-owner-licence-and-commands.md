# Human Test Checklist: a created project names its real owner, license and commands

**Target version:** 0.9.6
**Ships with commit:** `v0.9.6: fix: a created project names its real owner, license and commands`
**Companion automated tests:** `tests/test_github_owner.py` (5, gh stubbed), `tests/test_readme_blocks.py` (14), `tests/test_layer_action_pins.py` (3); full suite 281 passed, 14 skipped, 2 xfailed.

## What this is

0.9.6 changes what a person sees in a new project on day one:
- the owner in every URL, CODEOWNERS and FUNDING;
- the README badges, and the README and CONTRIBUTING commands;
- the license in `pyproject.toml` and the plugin manifest;
- the CI action versions, the labels, and `.repokit.json` being committed.

The automated tests stub `gh` and never open GitHub, never run the commands the README prints, and never wait for Dependabot. This checklist does those things, by hand, against throwaway repositories.

## Prerequisites

1. git-repokit 0.9.6 on PATH (`repokit --version`), `gh` logged in (`gh auth status`), Node 20+, CMake with vcpkg (for 2.2).
2. Work in a scratch folder **with a short path** (Windows path limit): `%TEMP%\rkc` (cmd), `$env:TEMP\rkc` (PowerShell), `/tmp/rkc` (POSIX).
3. **Scratch-git rules.**
   - Every hand-run create carries unsigned commits and closed stdin, so no signing prompt appears.
   - Never change global git config.
   - Run any git command against the scratch project with `-C <scratch path>`.
   - Set these first:

   **cmd.exe**:
   ```cmd
   set GIT_CONFIG_COUNT=2
   set GIT_CONFIG_KEY_0=commit.gpgsign
   set GIT_CONFIG_VALUE_0=false
   set GIT_CONFIG_KEY_1=tag.gpgsign
   set GIT_CONFIG_VALUE_1=false
   mkdir %TEMP%\rkc & cd /d %TEMP%\rkc
   ```

   **PowerShell**:
   ```powershell
   $env:GIT_CONFIG_COUNT = "2"
   $env:GIT_CONFIG_KEY_0 = "commit.gpgsign"; $env:GIT_CONFIG_VALUE_0 = "false"
   $env:GIT_CONFIG_KEY_1 = "tag.gpgsign"; $env:GIT_CONFIG_VALUE_1 = "false"
   New-Item -ItemType Directory -Force "$env:TEMP\rkc" | Out-Null; Set-Location "$env:TEMP\rkc"
   ```

   **POSIX**:
   ```bash
   export GIT_CONFIG_COUNT=2 GIT_CONFIG_KEY_0=commit.gpgsign GIT_CONFIG_VALUE_0=false GIT_CONFIG_KEY_1=tag.gpgsign GIT_CONFIG_VALUE_1=false
   mkdir -p /tmp/rkc && cd /tmp/rkc
   ```
4. Repository names used below are throwaways: `repokit-throwaway-<YYYYMMDD>-<n>`, private. You delete them afterwards (Cleanup).
5. Reset between sections: start each create in a fresh subfolder of the scratch folder.

## High-Value Verification (~10 minutes, needs GitHub)

### HV.1 -- No placeholder owner anywhere

- [ ] **Steps** (the create is the same in every shell):
  ```
  repokit create repokit-throwaway-YYYYMMDD-4 --language python --license mit --extras all --github --github-setup labels,issues,pin,discussions,topics --topics demo,cli
  ```
  Then search the tree, leaving out the vendored tooling:
  - cmd.exe: `findstr /s /m YOUR_GITHUB_USERNAME repokit-throwaway-YYYYMMDD-4\*` (ignore hits under `scripts\repokit-common`)
  - PowerShell: `Get-ChildItem -Recurse -File repokit-throwaway-YYYYMMDD-4 | Where-Object FullName -notmatch 'repokit-common' | Select-String -List YOUR_GITHUB_USERNAME`
  - POSIX: `grep -rl YOUR_GITHUB_USERNAME repokit-throwaway-YYYYMMDD-4 --exclude-dir=repokit-common`
- [ ] **Expected:** no matches. `.github/CODEOWNERS` names `@<your login>`.
- [ ] **Why this matters:** before 0.9.6 seven files kept the placeholder even with `--github`, so every badge and link on GitHub was broken.

### HV.2 -- The README on GitHub reads right

- [ ] **Steps:** open `https://github.com/<you>/repokit-throwaway-YYYYMMDD-4`.
- [ ] **Expected:**
  - Badges: CI status; Release (shows "no releases" until one exists); `python >=3.10`; `license MIT`; discussions.
  - The badge images may not render for a private repository; the links still resolve.
  - Installation, Usage, Development (prerequisites, setup, tests), Contributing and License sections, all with this project's own commands.
  - No "Feature 1", no "instructions here".
- [ ] **Why this matters:** the README is the first thing anyone reads, and it was a skeleton with false badges.

### HV.3 -- No Dependabot pull requests, and the labels the project uses exist

- [ ] **Steps:** wait two minutes after the push, then:
  ```
  gh pr list -R <you>/repokit-throwaway-YYYYMMDD-4 --state all
  gh label list -R <you>/repokit-throwaway-YYYYMMDD-4
  ```
- [ ] **Expected:**
  - No pull requests.
  - The labels include the nine house labels plus `bug`, `enhancement`, `dependencies`, `pip` and `github-actions`.
- [ ] **Why this matters:** stale action pins made Dependabot open three PRs on every new project, and the issue templates asked for labels that did not exist.

### HV.4 -- The record is committed, and the closing text is right

- [ ] **Steps:** `git -C repokit-throwaway-YYYYMMDD-4 status --short`, then `git -C repokit-throwaway-YYYYMMDD-4 ls-files .repokit.json`; read the end of the create's output.
- [ ] **Expected:**
  - The status is empty.
  - `.repokit.json` is listed, and its `author` holds your git name and email.
  - The output says `https://github.com/<you>/... is created and pushed next`, with no `github.com/username/repo` line.
- [ ] **Why this matters:** the record used to be left untracked in every project and never reached GitHub.

### HV.5 -- The license you chose is the one the package declares

- [ ] **Steps:** open `repokit-throwaway-YYYYMMDD-4/pyproject.toml`.
- [ ] **Expected:**
  - `license = {text = "MIT"}`;
  - the classifier `License :: OSI Approved :: MIT License`, and no GPL line;
  - `keywords = ["demo", "cli"]`.
- [ ] **Why this matters:** every Python package declared GPL whatever `--license` said, which would publish a wrong license to PyPI.

## Section 1: owners and the organisation

### 1.1 --org owns the URLs, the login owns CODEOWNERS and FUNDING

- [ ] **Steps:** in a fresh subfolder, the HV.1 create with `--org <an organisation you own>` added, and `-5` as the name suffix.
- [ ] **Expected:**
  - `CHANGELOG.md`, `ROADMAP.md`, `pyproject.toml` and the README links name the organisation.
  - `.github/CODEOWNERS` and `.github/FUNDING.yml` name your login.
  - The repository exists under the organisation.

### 1.2 No login known is said out loud

- [ ] **Steps:** `repokit create demo-nologin --language python --license mit --no-push`, with no `--github` and no `github.username` in `~/.repokit/config.json`.
- [ ] **Expected:**
  - One warning: `No GitHub login known: the URLs, CODEOWNERS and FUNDING say YOUR_GITHUB_USERNAME. Use --github, or set github.username ...`.
  - The "Next steps" lines name `github.com/YOUR_GITHUB_USERNAME/demo-nologin.git`.
  - Judge: is the warning clear enough to act on?

## Section 2: the README commands work as written

### 2.1 Python package

- [ ] **Steps:** in the HV.1 project, follow the README's Development block (venv, `pip install -e ".[dev]"`), then run its Usage and Tests lines.
- [ ] **Expected:** `<name> --help` and `python -m <package> --version` answer; the tests pass.

### 2.2 JavaScript/TypeScript and C/C++, without GitHub

- [ ] **Steps:**
  - `repokit create demo-js --language js-ts --license mit --no-push`, then run the README's setup and test lines (`npm install`, `npm run build`, `npm test`).
  - `repokit create demo-cpp --language c-cpp --license mit --no-push`, then run its setup lines (the two `cmake` commands, `VCPKG_ROOT` set) and `ctest`.
- [ ] **Expected:**
  - Each command runs as written.
  - The js-ts README shows a `node >=20` badge and no Python badge; the C/C++ README shows no runtime badge and no "build passing" badge.
  - CONTRIBUTING repeats the same setup and test commands.

### 2.3 The root CLAUDE.md

- [ ] **Steps:** open `CLAUDE.md` at the root of any project above.
- [ ] **Expected:**
  - A short file pointing at `private/CLAUDE.md`, with this project's setup and test commands.
  - Nothing about `setup.py build`, flake8 or a private branch.
  - No `private/claude/instructions/` folder.

## What the automated tests DON'T cover

- How the README and badges render on GitHub, including for a private repository
- Real `gh` label creation, and whether Dependabot opens anything after a real push
- Whether the README's commands run on a real machine (npm, CMake with vcpkg, a pip install)
- The wording of the no-login warning and the closing text, judged by a person
- `--org` against a real organisation's permissions

## Reporting issues found

1. Note the section and step.
2. Capture the exact command and output.
3. File an issue referencing this checklist and v0.9.6.

## Cleanup

- Delete the throwaway repositories you created: `gh repo delete <you>/repokit-throwaway-YYYYMMDD-4 --yes` (the same for `-5`). This needs the `delete_repo` scope (`gh auth refresh -h github.com -s delete_repo`), and deletion is permanent.
- Remove the scratch folder:
  - cmd.exe: `rmdir /s /q %TEMP%\rkc`
  - PowerShell: `Remove-Item -Recurse -Force "$env:TEMP\rkc"`
  - POSIX: `rm -rf /tmp/rkc`
- Unset the `GIT_CONFIG_*` variables, or close the shell.
