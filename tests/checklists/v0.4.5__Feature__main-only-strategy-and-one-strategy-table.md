# Human Test Checklist: main-only strategy, one strategy table, hook encoding

**Target version:** 0.4.5
**Ships with commit:** v0.4.5: feat: main-only strategy; branch strategies defined once
**Companion automated tests:** 90 passed, 13 skipped, 1 expected failure -- new: `tests/test_branch_strategies.py` (17), `tests/test_hook_encoding.py` (1)

## What this is

`repokit create --branch-strategy main-only` makes a single-branch repository with the project folder as the repository. The branch strategies now come from one table, and a strategy's own private branch is no longer overridden by `--private-branch`'s default. The guardrails hooks no longer crash on a console that is not UTF-8. This checklist covers what the suite cannot judge: how the new layout and messages look, and the hooks in a real terminal and a GUI client.

## High-Value Verification (~5 minutes)

### HV.1 -- main-only makes one branch, flat

- [ ] **Steps:** `repokit create demo --branch-strategy main-only --no-push`, then `git -C demo branch` and list `demo`.
- [ ] **Expected:** exactly `* main`; `demo/.git` exists; there is **no** `demo/local` and **no** `demo/github`; the closing message names the repository path and branch `main` and says `private/` is ignored.
- [ ] **Why this matters:** this is the layout new projects will get by default in the next slice.

### HV.2 -- nothing private is committed

- [ ] **Steps:** in a fresh scratch folder, `repokit create demo --branch-strategy main-only --ai claude --no-push`, then `git -C demo ls-files` and `git -C demo status --short`.
- [ ] **Expected:** no path under `private/` and no `CLAUDE.md` in `ls-files`; `CLAUDE.md` and `private/claude/` exist on disk; status shows at most `.repokit.json` as untracked.
- [ ] **Why this matters:** with no private branch, anything committed is on the public branch.

### HV.3 -- the legacy model still behaves

- [ ] **Steps:** `repokit create legacy --branch-strategy standard --no-push`; `git -C legacy/local branch`.
- [ ] **Expected:** `dev`, `live`, `main`, `private`, `staging`, `test`, with `* private`; `legacy/github` is on `main`.
- [ ] **Why this matters:** existing projects and anyone who asks for the old form rely on it.

### HV.4 -- `--private-branch` still wins when given

- [ ] **Steps:** `repokit create named --branch-strategy simple --private-branch scratch --no-push`; `git -C named/local branch`.
- [ ] **Expected:** a `scratch` branch, checked out; no `private` branch.

### HV.5 -- the help reads well

- [ ] **Steps:** `repokit create --help`.
- [ ] **Expected:** main-only listed first; the others under "Legacy branch model"; `--private-branch` says it defaults to the strategy's. Judge: is it clear which to pick?

## Section 1: Hooks on Windows

### 1.1 Commit from a GUI client or a piped shell

- [ ] **Steps:** in a scratch repo, `git init`, commit one file (with `-c commit.gpgsign=false`), `repokit setup-guardrails`, then commit another file from a GUI client (VS Code, GitHub Desktop) or with output piped: `git -c commit.gpgsign=false commit -m test 2>&1 | more`.
- [ ] **Expected:** the commit succeeds and the "RepoKit Pre-Commit Check" lines appear. Before the fix this failed with `UnicodeEncodeError`.

### 1.2 Existing projects keep their old hooks

- [ ] **Note:** projects created before this version still carry the old hook in their `.git/hooks`. Rerunning `repokit setup-guardrails` in such a project replaces it with the fixed one. Try it on a copy of one project, not the original.
