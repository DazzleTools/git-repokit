# Human Test Checklist: private modes -- nested, nested-branch, branch

**Target version:** 0.10.3
**Ships with commit:** v0.10.3 (TBD)
**Companion automated tests:** 30 in `tests/test_private_modes.py` (the modes, their defaults and refusals, the promoted folders, every private-branch strategy, the G4 flow through the real hooks), 1 in `tests/test_packaging.py` (the dependencies), and updated tests in `tests/test_common_guard.py`, `tests/test_new_default.py` and `tests/test_directory_profiles.py`. A red-green audit of 13 named mutants and a generated mutation sweep of 13 (`tests/mutation/v0.10.3__sweep__private-modes.md`) were all killed in the end.

## What this is

0.10.3 gives a private-branch project a third way to keep private work: `nested-branch`, now the default for a `create` with a private-branch strategy. `private/` stays its own repository, and `convos/`, `revisions/` and `logs/` are tracked at the root on the private branch only. This checklist runs real creates in a scratch folder. It checks what the automated tests cannot see: the worktree links on Windows, `minimal`'s branch switching on disk, a fresh Python 3.10 install, and how the messages read.

## Prerequisites

1. git-repokit 0.10.3 on the path (`repokit --version` prints `0.10.3`), git with `git subtree`, Python 3.10+ (and a 3.10 interpreter for 3.3).
2. For HV.4 only: git-repokit-common **0.4.4 or later** is what `create` vendors. Point `REPOKIT_COMMON_SOURCE` at a local checkout of it, or use the released subtree once 0.4.4 is pushed. With 0.4.3, HV.4's push is accepted; that is expected, and it is the gap 0.4.4 closes.
3. A scratch folder, never inside a real repository, with git fenced to it and signing switched off **for these commands only** (never change global git config):

   **cmd.exe**:
   ```cmd
   mkdir %TEMP%\rk0103 && cd /d %TEMP%\rk0103
   set GIT_CEILING_DIRECTORIES=%TEMP%\rk0103
   set GIT_CONFIG_COUNT=2
   set GIT_CONFIG_KEY_0=commit.gpgsign
   set GIT_CONFIG_VALUE_0=false
   set GIT_CONFIG_KEY_1=tag.gpgsign
   set GIT_CONFIG_VALUE_1=false
   ```

   **PowerShell**:
   ```powershell
   New-Item -ItemType Directory -Force "$env:TEMP\rk0103" | Out-Null; Set-Location "$env:TEMP\rk0103"
   $env:GIT_CEILING_DIRECTORIES = "$env:TEMP\rk0103"
   $env:GIT_CONFIG_COUNT = "2"
   $env:GIT_CONFIG_KEY_0 = "commit.gpgsign"; $env:GIT_CONFIG_VALUE_0 = "false"
   $env:GIT_CONFIG_KEY_1 = "tag.gpgsign";    $env:GIT_CONFIG_VALUE_1 = "false"
   ```

   **POSIX**:
   ```bash
   mkdir -p /tmp/rk0103 && cd /tmp/rk0103
   export GIT_CEILING_DIRECTORIES=/tmp/rk0103
   export GIT_CONFIG_COUNT=2 GIT_CONFIG_KEY_0=commit.gpgsign GIT_CONFIG_VALUE_0=false GIT_CONFIG_KEY_1=tag.gpgsign GIT_CONFIG_VALUE_1=false
   ```
4. Every `repokit create` below adds `--license mit --no-push --user-name T --user-email t@example.com`, written `<common>`.
5. Every git command names its repository with `-C`. Files are written with `python -c "open('PATH','w').write('x\n')"`, the same in every shell. **The only remote is a bare repository inside the scratch folder; never push to a real one.**
6. **Reset between sections:** each uses its own project name; Cleanup removes the scratch folder.

## High-Value Verification (~5 minutes)

### HV.1 -- a private-branch create is nested-branch

- [ ] **Steps:** `repokit create nb --branch-strategy simple --language python <common>`
- [ ] **Expected:**
  - `nb/local/.repokit.json` has `"private_mode": "nested-branch"`, and a `private_exposure` block with `private/`, `convos/`, `revisions/` and `logs/`, each `local`.
  - `nb/local/private/.git` exists, and the vault has `notes/` but no `convos/`, `revisions/` or `logs/` of its own (each folder has one home).
  - `nb/local/convos/`, `revisions/` and `logs/` exist; `logs/.gitignore` holds `*.log`.
  - `git -C nb/local ls-tree -r --name-only private` lists `convos/.gitkeep`, `revisions/.gitkeep` and `logs/.gitignore`.
  - `git -C nb/local log --name-only --format= main` and the same for `dev` list none of them, and no `private/`.
- [ ] **Why this matters:** the public branches are cut from the private branch and keep its history. If the folders had been in the first commit, every public push would carry them.

### HV.2 -- a plain add on private takes conversations and revisions, not run logs

- [ ] **Steps:** write `nb/local/convos/talk.md`, `nb/local/revisions/old.py` and `nb/local/logs/run.log`; then `git -C nb/local add .` and `git -C nb/local diff --cached --name-only`
- [ ] **Expected:** `convos/talk.md` and `revisions/old.py` are listed; `logs/run.log` is not. No `-f` was needed.
- [ ] **Then:** `git -C nb/local commit -qm records` succeeds (private is a private branch).

### HV.3 -- safe-merge leaves them behind; a hand merge is refused

- [ ] **Steps:**
  1. Write `nb/local/src.txt`, add it and commit it on `private`.
  2. `cd nb/dev` (the worktree; create it with `git -C nb/local worktree add ../dev dev` if absent), then `repokit safe-merge private`.
  3. `git -C nb/dev diff --cached --name-only`.
  4. `git -C nb/dev merge --abort`, then `git -C nb/dev merge --no-ff --no-commit private`, then `git -C nb/dev commit -m direct`.
- [ ] **Expected:** step 3 lists `src.txt` and nothing under `convos/` or `revisions/`. Step 4's commit is refused, naming the private files. Finish with `git -C nb/dev merge --abort`.

### HV.4 -- pushing the private branch is refused (git-repokit-common 0.4.4)

- [ ] **Steps:** `git init -q --bare nb.git`, `git -C nb/local remote add origin ../../nb.git`, `git -C nb/local push origin main dev`, then `git -C nb/local push origin private`
- [ ] **Expected:** main and dev push. The private push fails with `PUSH BLOCKED - Private Content Protection`, naming the promoted files and the overrides. `git -C nb.git branch` shows only `dev` and `main`.
- [ ] **Override, one push:** cmd `set REPOKIT_ALLOW_PRIVATE_PUSH=1` / PowerShell `$env:REPOKIT_ALLOW_PRIVATE_PUSH = "1"` / POSIX `REPOKIT_ALLOW_PRIVATE_PUSH=1 git ...`. The push lands. Unset it afterwards (`set REPOKIT_ALLOW_PRIVATE_PUSH=` / `Remove-Item Env:\REPOKIT_ALLOW_PRIVATE_PUSH`).

### HV.5 -- main-only is unchanged, and a branch mode there is refused

- [ ] **Steps:** `repokit create mo --language python <common>`, then `repokit create bad --private-mode branch <common>`
- [ ] **Expected:** `mo/.repokit.json` says `nested`; `mo/private/.git` exists; there is no `mo/convos/` or `mo/logs/`; `mo/.gitignore` still has `/convos/` and `/logs/`. The second create exits non-zero, names `--branch-strategy` and `--private-mode nested`, and there is no `bad/` folder.

## Section 1: branch mode (opt-in)

### 1.1 Warned, recorded, private/ on the private branch only

- [ ] **Steps:** `repokit create bm --branch-strategy simple --private-mode branch --language python <common>`
- [ ] **Expected:** a warning naming `--private-mode branch` and the default `nested-branch`. `.repokit.json` says `branch`. There is no `bm/local/private/.git`. `git -C bm/local ls-tree -r --name-only private` lists files under `private/`; main's and dev's history has none.
- [ ] **Check:** write `bm/local/private/notes/new.md`; `git -C bm/local add .` stages it without `-f`.

## Section 2: minimal (one checkout that switches branches)

### 2.1 The promoted folders leave the disk on main; the vault stays

- [ ] **Steps:** `repokit create mn --branch-strategy minimal --language python <common>`, then `git -C mn/local checkout main`, then `git -C mn/local checkout private`
- [ ] **Expected:** on `main`, `mn/local/convos/` and `revisions/` are gone (git hides files the public branch does not track; a leftover empty folder is fine), and `mn/local/private/` with its `.git` is still there. Back on `private`, they return.

### 2.2 Guardrails set up on main do not hide the folders on private

- [ ] **Steps:** in `mn/local` on `main`, run `repokit setup-guardrails`; then `git -C mn/local checkout private`; write `mn/local/revisions/x.md`; then `git -C mn/local check-ignore -v revisions/x.md`
- [ ] **Expected:** `check-ignore` prints nothing (exit 1), because the folder is not ignored. `git -C mn/local add .` stages `revisions/x.md`.

## Section 3: the install

### 3.1 A fresh Python 3.10 venv pulls the DazzleLib stack (AC6)

- [ ] **Steps:** from the git-repokit checkout, `python -m build`; then in the scratch folder `py -3.10 -m venv v310` (POSIX: `python3.10 -m venv v310`), and install the built wheel with that venv's pip; then run that venv's `repokit --version`.
- [ ] **Expected:** pip installs `dazzle-lib` (0.8.2 or later) and `dazzle-loglib` (0.3.3 or later), and `repokit --version` prints `0.10.3`.

### 3.2 The help reads well

- [ ] `repokit create --help`: the `--private-mode` entry lists `nested`, `nested-branch` and `branch`, and says which is the default for which strategy.

## What the automated tests DON'T cover

- Windows junctions for `private/` in each worktree, opened in Explorer or VS Code
- `minimal`'s checkout switching as seen on disk and in an editor
- A fresh Python 3.10 install from the built wheel (the suite runs from the checkout)
- A real hosted remote. **Never push private content to one**; skip it, or use a throwaway private repository you then delete.
- A real user's global gitignore (`core.excludesFile`). One case is simulated: the create still succeeds and says to add the folders by hand.
- How the warning and refusal messages read in a terminal

## Reporting issues found

Note the step, the exact command and output, the shell and the OS. File an issue referencing this checklist and v0.10.3.

## Cleanup

Delete the scratch folder: `dz safedel -r --yes <scratch path>` (recoverable), or your shell's delete if `dz` is not installed. Then unset `GIT_CEILING_DIRECTORIES` and the `GIT_CONFIG_*` variables (`set NAME=` / `Remove-Item Env:\NAME` / `unset NAME`).
