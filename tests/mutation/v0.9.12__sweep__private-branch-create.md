## Safety

Before the sweep, every test in the file was fenced with `GIT_CEILING_DIRECTORIES=tmp_path` (an autouse fixture). pytest's tmp_path sits under `%TEMP%`, which on the development machine is inside a home-directory repository, so a mutant that broke the worktree lookup could otherwise have committed into it.

The first run was interrupted by a session crash while a mutant was being written: `repo_manager.py` was left as zeros, because the harness keeps the original only in memory. It was restored from the red-green audit's aside copy (sha256 `394c285b...`, equal to the pre-sweep snapshot), and the sweep was re-run from the start. Both rounds below are from complete runs, and every restore verified byte-identical.

## Finding outside the scope

The tracked-file test, given a root `old.bak`, fails on the real code. The created repository's pre-commit hook (`repokit/templates/hooks/pre-commit.template`, with the same call in `repokit/branch_utils.py`) lists `git diff --cached --name-only`, which includes deletions. So the commit that removes `old.bak` from a public branch is refused as if it added it. `.gitignore` is then left modified and every later public branch fails, which 0.9.12 now reports. The defect predates 0.9.12 and is latent: a fresh create tracks no such file. It is recorded as `T7[root-bak]`, `xfail(strict=True)`.

## Caveats

A kill proves the suite noticed this change, not that it tests the right thing. A clean sweep is evidence about the mutations tried, not proof of suite completeness.
